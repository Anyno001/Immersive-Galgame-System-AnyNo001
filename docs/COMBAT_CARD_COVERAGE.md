### 全模板升级策略

`card-template-definitions.js` 是 275 个模板及 builder 的共享定义；`card-template-upgrades.js` 的 `TEMPLATE_UPGRADE_POLICIES` 逐键保存类别、升级路径／差值、来源引用及差异说明。新生成卡使用 `upgradeModel: template-v1:<模板键>`。加载时要求两者键集合完全一致，当前 missing / extra 均为空；新增模板漏登记会报错，不再静默省略升级。

| 策略类别 | 模板数 | 证据及适用边界 |
|---|---:|---|
| `source-component` | 127 | 有 `Game / Name / evidence`，只继承登记组件的升级轴；基础值、费用、目标和附加组件可能不同，不能宣称整卡原版等价 |
| `project` | 98 | 项目组合／自创升级，保留明确路径与差值，不主张原卡身份 |
| `unverified` | 50 | 原卡来源未核实；登记的是显式项目处理，不是原版升级证据 |
| 合计 | 275 | 全池有策略；来源核实只覆盖上述 127 项的指定组件 |

来源组件只控制对应轴，模板本体仍按项目费用／稀有度求解。下面是部分规则；完整逐键清单以注册表为准：

| cull / brace | Acrobatics / Backflip（Game 2） | 抽牌 +1／格挡 +3 |

### 运行与兼容契约

- `sourceModel` 要求登记卡面的类型、费用、稀有度、效果及升级字段相符；预算偏差仅保留诊断，不能改写来源数值。新版 `upgradeModel` 要求基础面可由对应 builder 生成，升级补丁／原因与策略精确一致；基础仍须满足项目预算。仅已核实的来源组件升级偏差保留诊断，`project / unverified` 升级继续接受通用预算检查。两标记互斥，伪造、越界及篡改拒收。
- 升级字段共用 `card-upgrade.js`：费用、效果、`innate / ethereal / retain / sly`、`onDiscard`，显式 `false` 表示移除关键字。新剧情／挑战／亲密局写 `cardUpgradeRules: 1`（须显式规则 v7）；无标记旧局仅合并费用和效果，恢复不补字段。开局固有按对应卡面处理，预览分别显示升级前后关键字。
- 并卡身份含 `sourceModel / upgradeModel / upgradeReason`，同机制但不同策略／原因不误并；缺省字段不进入键，未标记历史卡不新增身份。脱敏表适配器的写入、读回、并卡及快照重放已有定向回归。
- 对应 schema／机制单次值上限容纳来源升级：`create / shiv / soul` 数量 4、`grow` 10、`orb-slot` 3、`focus` 6、`smith` 14、`juggernaut` 8、`storm-heart` 2、`soul-blight` 9、首刃加伤 13。旧未标记首刃属性视图仍封顶 10，新 `template-v1:shiv-first` 封顶 13；累计强化上限不因此变化。

### 仍需核实的范围

- Hellraiser 对应的旧 `warrior-36` 仍是项目机制：抽到任意攻击牌向最弱敌人自动打出；它不在完整来源登记中。新增自定义模板 `hellraiser` 单独按名称含 Strike／打击触发，对随机敌人免费打出并已有结算回归，不替换旧固定卡，也不据此宣称整卡数值等价。
- `resonance` 的固有升级与 `surge` 的格挡 +3 均为显式 `project` 策略，不声称来源已核实；`resonance` 不因名称相近而附加虚无。
- 暗刃是项目 `shadow-shiv`，强化累计上限 20；回收、消耗等选择遵循项目已有交互。登记差异和运行链路验证不证明所有叠加、选择时点、目标与原版完全等价。Entrench 的 Event 仅存来源参考，模板稀有度独立求解，不作为完整固定卡进入奖励池。
- 固定卡全池及模板整体原版身份未逐张核验，50 项模板来源仍未核实；注册表自匹配不是 Cargo 对照证明，预算落窗率也不是升级模型等价证明。后续取得新来源证据时逐组件复核，不回写旧档案与 setup。
- 基础面匹配按模板缓存 builder 可产生的面；当前回归覆盖现有池，未做浏览器性能基准。若增加高维／大范围变量，需复核缓存成本。显式值回归重建每个可解费用／稀有度的代表解，不是所有变量组合的穷举。

前序 D-2 基线验证为 `combat-feedback.test.js` **41/41**，表读回与挑战会话合计 **13/13**；当时 235 个模板、6074 个可解变体（5966 个带升级、108 个带原因）。这些是历史批次结果，不冒充本轮重新执行的完整门禁。

本轮定向验证 **29/29**：全 **275 个键、6915 个可解变体**通过规范化、预算及代表解的显式值重建，其中 **6788 个带升级、127 个带显式无升级原因**；覆盖基础面／升级／原因篡改拒收。生产 `generateEntities` 验证新增 40 项职业白名单、模板提示、策略身份、升级物化与回放，另保留既有正式生成与余烬新旧快照回归。新增 40 项均有下表对应的直接结算断言及确定性回放。挑战／亲密新局保存标记、恢复不补旧局字段的定向回归另 **1/1** 通过。

使用脱敏 Node 夹具与确定性模型替身，不代表真实模型任意回复、全部显式值组合或全卡实战审计。真实酒馆、手机和现场存档未终验；来源补证与浏览器缓存性能复核按对应范围触发，整体平衡留待 D-3。本阶段不进入 D-3，不执行完整门禁、构建、升版、暂存、提交、推送或标签。

### 余烬与验收边界

新局 `exhaustRules: 1` 将能力牌正常离场与真实消耗分开：正常离场不触发余烬，效果消耗能力牌及能力牌的本牌消耗均触发；无标记旧 setup 不补字段，按历史语义重放。新局消耗堆计数只计 `realExhaust === true` 的实例。

逐项表证明上述项目定义的核心结算，不证明任意组合、全部来源版本或原作完整数值等价；额外回合、自动出牌内层选择、自动预知、衍生牌及资源上限按表中项目边界运行。原始参考仍为 679 条代表性快照；50 项来源未核实策略、浏览器缓存性能与整体平衡分别留待对应补证或后续阶段。
