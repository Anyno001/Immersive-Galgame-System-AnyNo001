## 一、读人设：按世界书条目取

- 现状：`app/src/core/bootstrap.js:866-871` 只在角色卡名字精确命中时取 description/personality，世界书只按角色名做关键词扫描，条目关键词是别名（妖皇、龙太子）时取不到，人设送空；读取失败被空 catch 吞掉。
- 改法：
  1. 世界书扫描时把角色名和别名组（`characterAliases`）一起送去扫；条目标题（comment）或正文开头含角色名、别名的也算命中。
  2. 仍为空时，从最近楼层正文截取包含该角色名或别名的段落作兜底。
  3. 读取失败记诊断，不再静默。
  4. 「复制本页诊断」输出每个角色送去的人设字数。

## 二、评定改用「标签思路」

用户定：评选模型先用标签思路理解角色，再对照特质表。

- 提示词改为两步：
  1. 先为每个角色从人设与正文概括 3–8 个标签（性格、身份、能力、种族，如「强者为尊」「冷酷」「妖族」「龙族」「掌权者」）；
  2. 再按标签去特质表里挑最贴近的特质，返回时附上依据的标签。
- 默认 judge 文案由「人设写明其「X」的特点」放宽为「人设或言行体现出「X」」；可以由人设概括得出，不要求字面一致。
- 标签只用于评定，存进诊断，不进正文提示词、不显示在界面。

### 捆绑特质（11-08 用户提出）

挂上某个系时，强制带上若干捆绑特质，不能单独摘下，用来增加难度（有得有失）。「逆鳞」定为龙系的捆绑特质，不单列心性组。

机制草案：
- 捆绑特质存为 `{ on: true, src: 'bound', by: 系名 }`，胶囊显示在所属系后面，说明卡标「随龙系附带，不能单独摘下」。
- 手动摘下、自动评定、互斥替换都不能摘捆绑特质；摘下所属的系时一并摘下。
- 捆绑特质与已挂特质互斥时，捆绑特质优先，顶掉旧的。
- 捆绑特质不受六维门槛限制（它属于种族或天性）。
- 占格（11-08 用户定）：**捆绑特质占格**，免得玩家看到什么都往上加；挂系前格子不够放下整套捆绑时，按现有满格规则处理（手动拒绝、剧情顶掉最早的自动项）。
- 人设豁免（11-08 用户定）：人设写明了与某个捆绑项相反的性格时（例如懦弱的小蛇不该带「记仇」），评选模型可以标记免掉这一项捆绑；手动添加本体时不能豁免。豁免记录存在本体条目上，如 `{ on: true, waived: ['记仇'] }`，胶囊说明卡写「人设豁免：记仇」。只有下表标为「可豁免」的捆绑能免；种族、身份类的硬性捆绑标为「不可豁免」，评选模型给出的豁免一律丢弃并记诊断。

全量捆绑表（11-08 全量筛选，多数复用现有特质，每个本体只捆一项，尽量有得有失）：

筛选原则：
- 本体多为优势时捆一个代价，本体多为代价时不捆或捆一个补偿；只捆天然伴随的特质，不为凑数而捆。
- 双向特质（共犯、已标记、信息素契合、精神结合、认出蛋糕、伴侣印记、血契、主从契约）不做本体；恩情、仇怨关系状态不做本体。
- 捆绑不连锁：捆绑项自身若也是本体，不再触发它的捆绑。本表的捆绑项均不是本体，目前不存在连锁。
- 捆绑项的「主角可用」与本体一致（本体主角可用时，捆绑项也主角可用）；捆绑项为仅NSFW特质时，NSFW关闭期间不附带。
