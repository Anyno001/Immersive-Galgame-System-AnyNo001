# 数值系统「升太快 / 扣太狠」普查（11-11，本地不推）

范围：app/src/scene/stats/。只列有数字推演的疑点；没核完的标「未核实」。习惯机制相关的顶撞三重罚已在 docs/STATS_HABIT_PLAN.md 处理，这里只做交叉引用。
默认口径：rev ≥ 2 新楼、普通档（单楼好感 +8、每日 +12，stat-favor.js:31–34）。

## 汇总

| # | 问题 | 严重程度 |
|---|---|---|
| 1 | 芥蒂上升没有单楼和每日上限 | 高 |
| 2 | 好感、信任的负向没有每日上限，与正向上限严重不对称 | 高 |
| 3 | 特质钩子 `bump` 绕过单楼和每日上限，且多数每楼都触发 | 中高 |
| 4 | 鸟系重逢可每楼重复触发 | 中 |
| 5 | 压力标签同楼不去重、没有单楼上限 | 中 |
| 6 | 白月光 / 鸟系「重逢」事件不限次数 | 中低 |
| 7 | 声望标签没有每日上限 | 低 |
| 8 | 冷战掷骰在时间跳跃后一次扣满 | 低 |

## 1. 芥蒂上升没有单楼和每日上限（高）

- 位置：stat-favor.js:342–348 `applyGrudgeTier`。上升 `delta = GRUDGE_UP_BASE[level]`（小 2 / 中 5 / 大 10 / 重大 20，stat-vocab.js:54），注释写明「不设单楼与每日上限」；只有下降有每日 −10（:337）。
- 叠加来源：正文标签、雷点重雷 +2（stat-trait-landmines.js:29）、女王·拒绝 +2（stat-trait-rules-e2a.js:165）、控制狂·拒绝 +2（stat-trait-rules-fixup.js:195）、龙系·批评补 50%（stat-trait-rules-review.js:43）、自恋·批评补一份（:44）、失约 +2（stat-trait-rules-e2b.js:184）、吃醋另有账（stat-favor.js:271–301）。
- 推演：一天 3 楼冲突，AI 每楼写「芥蒂|上升|中」→ +15/天；再加重雷 +2×3 → +21/天。从 0 起：第 2 天 42（记恨），第 3 天 63（怨恨）。只写「小」也是 +2+2=+4/楼，6 楼到 24。离渊案例就是这条叠第 2 条。
- 消退：只有芥蒂 > 25 每天 −1，最低回到 25（stat-favor-events.js:81–89）；从 63 淡到 25 要 38 天。涨 3 天、消 38 天。
- 建议：芥蒂上升加单楼上限（建议 5，等于「中」档）与每日上限（建议 10，与下降对称）；「大」「重大」与 event:背叛 / 结怨 / 血仇等事件型来源不受单楼上限限制，但计入每日。特质钩子的芥蒂加成也计入同一额度。

## 2. 负向没有每日上限，正负不对称（高）

- 位置：stat-favor.js:168–172。负向 `delta = FAVOR_NEG_BASE[level]`（小 −3 / 中 −8 / 大 −15 / 重大 −25），只在有特质下降倍率时才走 `guardDrop`（单楼 30）。无特质时**连单楼保护都没有**（其实单楼最多一条，因为 dedupeDims 同楼同角色只留一条，stat-settle.js:226–240，所以单楼上限等于 25）。
- 正向：普通档单楼 8、每日 12，且要掷骰过「d100 > 当前好感」才拿全额（stat-favor.js:206–212）。
- 推演：好感 40 的角色，一天里 AI 3 楼写「不满」（省略强度＝中）→ −24；要涨回来，按每日上限 12、且好感 40 时掷骰通过率 60%（失败减半）期望约 +9.6/天 → 需约 2.5 天。写一次「受伤」（默认大，−15）就抵掉一天多的上限。
- 「不满」「嫌弃」「愤怒」「吃醋」「害怕」默认都是「中」（stat-vocab.js:22–26），AI 很少写强度，负面情绪一律按 −8 结算，是「扣太狠」的主要来源。
- 信任同理：TRUST_DOWN_BASE 中 −8 / 大 −15 / 重大 −30（stat-vocab.js:60），上升单楼 6、每日 10（stat-favor.js:306–307）。
- 建议（二选一或并用）：
  - 负向加每日上限：好感 −20/天，信任 −20/天；有 event（背叛、谎言揭穿、关键事件大失败）的那一楼不受限。
  - 或把 `不满`、`嫌弃` 的默认强度从「中」降为「小」（只改 FAVOR_WORDS，stat-vocab.js:22–23），「愤怒」「害怕」保留「中」。改默认强度只影响新楼，旧楼重算按 strengthRev 走旧规则需另外确认（未核实）。

## 3. 特质钩子 `bump` 绕过上限（中高）

- 位置：stat-trait-hooks.js:28–37 `bump`：只做关口封顶，不读也不写 `daily.gained` 和 `ctx.floorGained`。规则文件的加分（api.bump、moveDim、dim）同样如此（stat-trait-rules-e2b.js:75–83 等）。
- 每楼都会触发、没有每日一次限制的例子：
  - 熊系：主角受伤那一楼好感 +6（stat-trait-hooks.js:92）。
  - 护短：主角受伤或大压力那一楼好感 +2、信任 +1（:87–90）。
  - 慕强者：主角检定成功或战胜那一楼 +2（stat-trait-rules-persona.js:141）。
  - 自卑 / 自恋：被夸奖那一楼补一份标签已给的量（stat-trait-rules-review.js:41）。
  - 害羞鬼、事后黏人：亲密那一楼 +2（stat-trait-rules-persona.js:138、stat-trait-rules-extreme.js:188）。
  - 花心：补 50%（stat-trait-rules-fixup.js:188–190）。
- 推演 A（熊系 + 护短，同一角色）：连续 4 楼战斗，主角每楼带伤。每楼标签 +8（单楼上限）+ 熊系 6 + 护短 2 = +16/楼；4 楼 = +64。每日上限 12 只拦了标签那部分（第 2 楼起标签只剩 4、之后 0），实际 = 8 + 4 + 0 + 0 + 8×4 = **+44/天**，是上限的 3.7 倍。好感 0 起一天到「明确喜欢」后段（受 25 关口封顶时会卡在 25，所以实际冲过 25 前不会爆；关口已解锁的后段才明显）。
- 推演 B（自恋，被夸奖）：每楼标签 +8、自恋补 +8 → +16/楼；标签部分到每日 12 封顶后，补的那份读「本楼标签已给的量」，会跟着降为 0 → 当天合计约 24，是上限的 2 倍。
- 建议：给 `bump` 加可选的「计入额度」参数：正向好感 / 信任的加成计入 `ctx.floorGained` 与 `daily.gained`，超出的部分截掉并在明细写「每日上限」；或者给每楼触发型规则统一加「每角色每日一次」（参照 e2b 的 `once`，stat-trait-rules-e2b.js:54–59）。熊系、护短更适合「每日一次」，自恋 / 自卑 / 花心这类「补一份」更适合计入额度。

## 4. 鸟系重逢可每楼重复触发（中）

- 位置：stat-trait-rules-romance2.js:170–181。判定 `day − ctx.lastSeen[名] ≥ 7 且在场`，命中后好感 +4（FAVOR_STEP，:16）。白月光那条在命中后写 `lastSeenDay = day`（:165），**鸟系没有写**。
- lastSeenDay 只在该角色收到 favor / dim / gift / event 标签时更新（stat-settle.js:594），或时间跳跃时在场（stat-day.js:146）。
- 推演：鸟系角色隔 8 天回来，之后同一天连续 5 楼在场，但 AI 只写了 traitEvent（顶撞 / 夸奖）或没给 TA 写标签 → 每楼 +4，共 +20；钩子不计每日上限（见第 3 条）。如果一直没有好感标签，这条会每楼持续触发直到过天后时间跳跃。
- 建议：鸟系命中后同样 `putField(lastSeenDay: day)`；或两者都改成写 `reunionDay`，同一天只触发一次（与习惯计划第 7 节共用同一字段）。

## 5. 压力标签同楼不去重、无单楼上限（中）

- 位置：stat-settle.js:693–709 `settleBars` 逐条结算主角压力；`dedupeDims` 只管 favor / dim（:230）。档位：小 5 / 中 10 / 大 20 / 极大 50（stat-bars.js:10）。特质倍率夹在 ×0.5–×2（stat-traits.js:21–22），脆弱 ×2（:922），温柔疏离做失望类事件时再 ×2（stat-settle.js:769，连乘后仍夹在 2）。
- 推演：脆弱主角，一楼里 AI 写了两条「压力|上升|大」（不同来源，如「被迫」「受辱」）→ 20×2×2 = +80；一楼从 10 到 90。普通主角同样两条大 → +40。日结算只 −10。
- 建议：主角压力同楼按来源合并、只留最大一条（与好感 dedupe 一致），或加单楼上限（建议 +30，极大档不受限）。情绪稳定的 `stressCapMid`（:740）已是同类做法，可以泛化。

## 6. 白月光「重逢」事件不限次数（中低）

- 位置：stat-trait-rules-romance2.js:159–164。`reunion.includes(name)` 分支没有「久别」条件，也没有每日一次；AI 每楼写一次 `event:重逢` 就 +6（BIG.好感）。
- 推演：同一天 3 楼都写了重逢（AI 把整段重逢戏拆成多楼时常见）→ +18，加上标签 +12 封顶 → 一天 +30。
- 建议：与第 4 条共用 `reunionDay`，每角色每日一次。

## 7. 声望标签没有每日上限（低）

- 位置：stat-fame.js:262–300。同条同楼只留一条最大的，强度 小 2 / 中 5 / 大 10（:12），没有每日上限；热度、威胁每天 −2（:27–31）。
- 推演：一天 5 楼都写「热度|上升|大」→ +50，自然回落要 25 天。
- 判断：声望本来就由剧情驱动，可能是有意设计；只在用户反馈「一天就满」时再加每日上限（建议 20）。

## 8. 冷战掷骰在时间跳跃后一次扣满（低）

- 位置：stat-trait-landmines.js:443–476。`n = min(7, days, elapsed)` 次掷骰，命中率 = 芥蒂（夹在 20–80%），每次 −3。
- 推演：芥蒂 80 的冷战角色，一次跳过 7 天 → 期望 7×0.8×3 ≈ −17，最坏 −21。逐日过和一次跳过期望相同，所以不算 bug；只是玩家看到的是一次跳 −17。
- 判断：符合设计，记一笔。若要缓和，可把跳跃时的命中按天折半。
