# 数值关系第二轮计划（压测修补 / 友情 / 悟性 / 压测脚本）

2026-11-07 用户定稿方向。本地文档，不推送。

前置：`STATS_STRENGTH_EXPANSION_PLAN.md`（强度扩展）已实施、未提交，验收进行中。本计划在其之上改，**新楼标记沿用 `strengthRev`**：本轮改动凡影响结算的，都只对 `strengthRev ≥ 2` 的楼生效，新楼写 2；旧楼（无标记或为 1）重算结果不变。讨论记录见 `STATS_RELATION_STRESS_TEST_NOTES.md`。

## 用户定的规则

- NPC 与 NPC 之间的关系不碰，交给世界书与正文。
- 关系名只给用户看，不注入提示词。
- 悟性：天才也要越高越难提升。
- 顿悟通用，日常题材也能用。
- 非自愿造成的伤是真实伤害，照记；双方同意的玩法中的疼痛不记。
- 主角没有好感条，这是设计，不补。
- 设置页文案书面语，不写数字，不用口语。

## 一、提示词修补（tags 段总则）

在强度扩展已落地的 tags 总则上改。总则改成以下五条（第 1、3 条原有，其余新增或合并）：

1. 关系类标签只记角色对主角态度的变化，不记角色此刻的情绪。角色因他人或与主角无关的事高兴、生气、迁怒，或误会尚未落到主角身上时，不写。主角自己的心意与情绪不写关系标签。（原有，11-07 补末句）
2. 亲密行为本身不算好感事件，只按主角在过程中的态度判断。压力按主角在过程中的感受写：放松为下降，紧张、担心、被迫为上升。伤势只记真实受伤：双方同意的玩法中的疼痛不写，非自愿造成的伤照写。
3. 吃醋只在角色真的因此对主角不满时写，乐在其中或只是玩笑时不写；吃醋已含芥蒂，不另写芥蒂标签。（原有）
4. 身份：角色伪装或身份未揭晓时，按真实身份写；被附身时按当下掌控身体的意识写；群体不写关系标签，只对具名个人写；不为代词、无名者或临时称呼建档。关系标签记角色对主角这个人的态度，不记对其身体的态度。
5. 强度释义（原有）。补半句：好感省略按方向词默认强度，信任、芥蒂省略按小，压力省略按中。

占位符：`{{好感强度}}` 改名 `{{强度}}`（信任、芥蒂共用）。用户自定义 tags 里写的 `{{好感强度}}` 继续填同一内容，不报未知占位符。

## 二、结算修补

### 2.1 亲密不再固定减压力

`stat-settle.js` `settleIntimate`（约 270 行）：当天第一次亲密主角压力 −10 的逻辑，`strengthRev ≥ 2` 的楼去掉，交给 stress 标签。旧楼保留。

### 2.2 吃醋与芥蒂防双算

同楼同角色同时有吃醋好感标签与芥蒂上升标签时，芥蒂上升标签丢弃，记诊断 `stat-grudge-with-jealous`。芥蒂下降标签不受影响。位置：`stat-settle.js` `dedupeDims` 之后。

### 2.3 芥蒂缓慢消退

每次日结算（含时间跳跃，按跳过天数），芥蒂 >25 的角色每天 −1，最低降到 25，不掉回吃醋低路。芥蒂 ≤25 不消退。变动记录 note 写「淡忘」，多天合成一条。位置：`stat-favor-events.js` 与 `coolDown` 同处调用（`stat-day.js` 日结算链）。

### 2.4 情绪组兜底调整

计划第八节的 `MOOD_GROUP_FAVOR`：

- 哭泣组：受伤·大 → **悲伤·小**。哭的原因太杂（感动、玩法、委屈），兜底误判时损失要小。AI 明确写「受伤」仍按大算。
- 大笑组：喜悦（正·小）→ **平淡**。发疯大笑、嘲笑都在这一组；正向已有喜悦组覆盖。AI 明确写「大笑」方向词仍按正·小算。

只改兜底表，不改 18 个方向词本身。

### 2.5 补近义词

`favorNew` 表补：崇拜、敬畏、仰慕 → 欣赏；狂热 → 爱恋。

## 三、新事件

`KEY_EVENTS` 现为 约会 / 告白 / 共患难。新增两个：

### 3.1 交心（友情向关口事件）

`[igs-stat:event|角色名|交心]`：深谈、托付秘密、并肩扛事。与其他关键事件同规则（停在关口时掷魅力检定突破）。提示词 event 行加「交心」并在说明里写一句「交心用于朋友、家人等非恋爱关系」。

### 3.1.5 关键事件按类型选检定

`stat-settle.js` 约 130 行 `applyKeyEvent` 的 roll 现固定用主角魅力。改为：告白、约会用魅力；共患难用主角格斗类或体质中最高者；交心用察言观色与魅力中较高者。技能名以 `stat-registry.js` 实际存在的为准，实施方核对。战斗与日常挑战里的共患难（`stat-battle.js` 126 行、`stat-challenge.js`）同改。

### 3.2 误会解除

`[igs-stat:clear|角色名]`：误会澄清。一次性退回该角色近 7 天内带「误会可退」标记的信任下降与芥蒂上升的一半（四舍五入，至少 1），每个角色每次误会只能用一次。

实现取舍：系统无法知道哪次下降是误会。做法——近 7 天内该角色的信任下降、芥蒂上升都记一份账（`character.recentHurts`，存日、维度、量），clear 时把账里的量退一半并清空账。超过 7 天的自动作废。提示词：「误会澄清、真相大白时写，不写数字」。

## 五、悟性与顿悟

### 5.1 悟性

角色字段 `aptitude`：平庸（默认）/ 出众 / 天纵。主角在「我的角色」手选；开局评定（`heroSkills` / `sheetGen` 提示词）按人设给档，人设写了天才、天之骄子之类才给出众以上。NPC 同样可有。

| 档 | 成长检定 | 涨幅 | grow 标签 |
|---|---|---|---|
| 平庸 | d100 > 当前值 | 1d10 | 每天一次 |
| 出众 | 两次取好 | 1d10 | 每天一次 |
| 天纵 | 两次取好，判定线按当前值 −10 | 1d10+2 | 每天两次 |

上限 90 不变，越高越难。位置：`stat-day.js` `growSkills`（约 48 行）、`growNpcSkills`；`stat-settle.js` `settleGrowTags`（约 56 行）。

### 5.2 顿悟

`[igs-stat:insight|角色名|技能名]`：剧情明确写了想通、开窍、豁然贯通，或生死关头、闭关等关键时刻。一次 +2d10，不超过 90；同一角色同一技能每 30 天最多一次。通用，不限题材。

## 六、时间跳跃上限

`stat-duration.js` 第 2 行 `SKIP_DAYS_MAX = 30`，分居数年会被截成 30 天。改为 3650（10 年）。跳跃后 `coolDown`（好感每天 −1，止于当前阶段下限）、`resetDaily` 的受伤天数、2.3 的芥蒂消退按天数一次算完，不逐日循环。核对 30 以上天数的性能与 `capped` 诊断。

**跳跃楼在场角色不冷却（11-07 用户定）**：时间跳跃那一楼的在场角色（settle opts `present`）视为跳跃期间一直在主角身边：跳跃结算前把其 `lastSeenDay` 视作跳跃后的日子，`coolDown` 不扣。不在场的角色照旧冷却。只对 `strengthRev ≥ 2`。来源：压测「养成线同住十年」。

用户 11-07 明确**不加**「未成年角色不写欲望与亲密标签」：会误伤双方同意的高中生恋爱与外表年幼、实际千岁的角色。年龄交给正文与世界书，数值系统不判断。

## 六点五、随身与无身体（主角离体、随身老爷爷 / 系统、灵宠）

用户 11-07 定要补。讨论见压测笔记第八节。

- 标签 `[igs-stat:hero|离体/复归]`，状态存 `protagonist.detached`（布尔），状态栏显示「离体」。
- 离体期间冻结：主角体力、金钱、伤势；进食、入睡漏打兜底（`stat-day.js` `fallbackDirectives`）；亲密扣主角体力（`settleIntimate` 只扣对方）；主角检定（roll 标签、社交检定约束好感）。
- 离体期间保留：主角压力（灵魂的感受）；NPC 对主角的关系标签照常结算；时间与日结算照常。
- 离体期间所有角色的好感冷却（`coolDown`）暂停，对逝者的感情不自动变淡。
- 提示词：tags 生活块加一行 hero 标签说明「主角死亡、昏迷、灵魂离体或失去身体控制时写离体，回到身体时写复归」。
### 角色的两个标记（互相独立）

| 标记 | 含义 | 效果 |
|---|---|---|
| 随身 | 一直跟着主角，正文不点名也在 | 不做好感冷却；在场名单默认在场 |
| 无身体 | 没有实体（残魂、器灵、系统） | 不结算该角色的体力、亲密、伤势；带其名的 stamina / intimate / hurt 标签丢弃，记诊断 `stat-bodiless` |

- 例：戒指里的老爷爷、有人格的系统＝随身 + 无身体；开灵智的灵宠、契约兽、小精灵＝只有随身（有实体，体力、伤势照算）；离体的主角＝套用无身体规则。
- 设置方式：角色档案两个勾选项；或起始关系修饰 `+随身`、`+无身体`（加进 `START_MODIFIERS`，可叠加，如 `亲密+随身+无身体`）。
- 修罗场仍只认「当过恋爱对象」，随身不改变这一点。
- 灵宠暂时离开（收进灵兽袋、外出）时不改标记，随身角色一律不冷却，简单优先。
- 名字为「系统」的角色与侧栏「随身系统」功能模块互不相干；实施时核对二者不会因同名串数据。

- 与第八节「死亡状态」合并：本节落地后，死亡状态一项只剩 NPC 死亡待核。
- 只对 `strengthRev ≥ 2` 生效。测试：离体时 intimate 不扣主角体力、兜底不补进食、冷却暂停、复归后恢复；随身角色不冷却；无身体角色的 stamina / hurt 标签丢弃；灵宠（仅随身）体力照扣。

## 七、压测脚本

`app/tools/stats-stress/`（不进 build、不进测试）：每个场景是一串按楼的预设标签 + 时间推进，直接调用结算，不调 AI。输出双击即开的 HTML：每个场景一张好感 / 信任 / 了解 / 芥蒂四线图，下方每楼一行（标签、变动、关系名）。三档成长各跑一遍。

场景（详见 `STATS_RELATION_STRESS_TEST_NOTES.md` 第三、五–七节）：青梅竹马纯友情、家人兄妹、欢喜冤家、前任爱恨交织、背叛后和解、宿敌惺惺相惜、暗恋、修罗场多角、师徒主仆、困难档 30 天长线、性质转变（收养妹妹）、误会→真相（青梅竹马男友）、癖好反转、BDSM 入门、夫妻情绪玩法、非自愿（舞会后台）、邪教崇拜、附身、轮回、主角离体（艳尸）、随身老爷爷、灵宠、死士单恋国王（检查主角心事是否被写成国王好感、共患难能否带死士过关口）。

每个场景写「期望」一栏（关系名区间、几楼恢复等），脚本标出不符合期望的楼。

## 八、不做 / 待观察

- NPC 之间的关系（用户定不碰）。
- 「角色心情」数值（与表情差分重复）。
- `reset` 剧情强制改值（洗脑、失忆、轮回）：压测后看是否常用再定。
- 死亡状态、CoC 理智与压力是否重复：压测时核代码，结论写回本文档，不在本轮改。

### 11-07 核查结论

1. reset 剧情强制改值：现有标签只有 dim 方向加减（带强度档，受每日上限与阶段下限约束）、clear（只退回近 7 天误会账的一半）、romance 结束、hero 离体，没有「直接置为某值」或「清空某人档案」的标签（stat-directives.js 的 case 列表）。洗脑、失忆、轮回现在只能靠多次下降或 time skip 慢慢冷却，表达不了。缺的是一个绕过每日上限的置值/清零标签（如 `[igs-stat:reset|角色|维度|值]`），并同时清误会账与 lastSeenDay。建议先不做，等压测出现真实需求再定。
2. NPC 死亡状态：代码里没有任何死亡标记（只有主角 hero 离体、战败不会死亡的说明）。已死 NPC 的好感、欲望、芥蒂仍会按日冷却与淡去，只有主角离体和「随身」角色会暂停（stat-day.js coolCharactersRev2）；在场由正文点名决定，故不会再出现在在场列表，但正文追忆时点名会重新算在场、可能被再次建档或写词。问题：已故者的关系数值会在数日后悄悄衰减，与剧情不符。属小问题，可复用「随身」式特征标记做一个「已故」冻结位，本轮不改。
3. CoC 理智与压力：没有重复计算。理智是 CoC 第七属性，只作为检定目标值（stat-engine.js 的 sanOf 与 isSan），代码里没有理智损失或恢复的结算；压力是生活条，仅在 >70 时让检定目标值 −10（stat-bars.js checkModifiers），并由日结算 −10 恢复。语义上有重叠（都表示精神状态且都影响检定），但属于不同来源叠加，无同一事件双算。唯一的叠加是：压力高时连理智检定也 −10，可接受，建议不改。
