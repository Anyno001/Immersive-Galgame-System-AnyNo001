# 好感成长三档计划（鲜明 / 普通 / 困难）

2026-11-06 用户定稿。本地文档，不推送。

## 背景

现行普通档（`stat-favor.js`）：方向标签增量 开心 +2、感动/心动 +3；正向先掷 d100，大于当前好感才全额，否则只 +1；单楼 +3、每日 +8；关口 25/50/75 需关键事件突破。好感 40 时约六成只 +1，70 以上几乎每次 +1。负向 失望 −2、吃醋 −3、受伤 −6，轻重差别小。用户反馈「增减不明显」。

## 用户定的规则

- 分三档：**鲜明**（新默认）＝强度档 + 阶段折扣 + 心意槽；**普通**＝现行普通档改良（C）；**困难**＝现行普通档原样。旧困难档（单楼 +1、每日 +4）取消。
- AI 仍只给离散档位，不写数字。
- 负向加重、关口规则三档共用；送礼、日常挑战、关键事件突破不受档位影响。
- 心意槽只属于鲜明档。

## 一、标签：新增可选强度字段

`[igs-stat:favor|角色名|方向|强度]`，强度为 `小/中/大/重大`，第四段可省。

- 近义词归一写进 `stat-vocab.js` SYNONYMS（轻微→小、一般→中、强烈→大、决定性→重大 等），含数字整条丢弃，规则同现有档位。
- **省略强度时按方向推定**（兼容自定义过提示词的用户，不必手动更新）：开心→小，感动、心动→中，平淡→无，失望→小，反感、吃醋→中，受伤→大。
- 正向「重大」只在同楼对同一角色有 `event` 标签（约会/告白/共患难）时成立，否则降为「大」；负向「重大」用于背叛、决裂，不需要 event。
- 检定失败的现有降档（`FAVOR_DOWNGRADE`）照旧，并把强度再降一档（小降为无）。

## 二、三档数值

正向基础值（鲜明、普通共用）：小 +2，中 +5，大 +10，重大 +15。

| | 鲜明 | 普通 | 困难（＝现行普通） |
|---|---|---|---|
| 增量来源 | 强度基础值 × 阶段倍率 | 强度基础值 | 方向表（开心 2、感动/心动 3） |
| d100 | 不掷 | 大于当前值全额，否则减半（至少 1） | 大于当前值全额，否则 +1 |
| 单楼上限 | 15 | 5 | 3 |
| 每日上限 | 按阶段 15 / 12 / 10 / 8 | 8 | 8 |
| 心意槽 | 有 | 无 | 无 |

- 阶段倍率（鲜明）：当前好感 ≤25 ×1，26–50 ×0.8，51–75 ×0.6，>75 ×0.4；四舍五入，至少 +1。负值区间按 ×1。
- 鲜明档同一角色每天最多一次「大」，第二次起按「中」算（记在 `character.daily`，日结算清零）。
- 关口封顶 `gateCap` 三档照旧。

负向（三档共用，不打折扣、不设上限）：小 −3，中 −8，大 −15，重大 −25。困难档负向也改用此表（方向推定强度后查表）。

信任、了解、芥蒂等其他维度本轮不改。

## 三、心意槽（鲜明档）

- 角色状态新增 `heart`（0–4，隐藏，不进状态栏、不推表格）。随楼层快照保存，swipe、删楼自然一致。
- 鲜明档正向「小」不直接加好感，而是把折算后的增量加进槽；槽 ≥5 时好感 +5（受关口与每日上限约束），槽减 5，变动记录 note 写「心意满溢」，并发一个 `burst` 演出事件。
- 中及以上的正向照常直接加，不进槽、不清槽。
- 负向「中」及以上清空槽；负向「小」槽 −2（不低于 0）。
- 切到普通或困难档后槽保留不用，切回鲜明继续累计。

演出：沿用现有好感飘字（`fx-runtime.js`），`burst` 时用更大的心形与「心意满溢」小字；遵守演出美术规则（实色、不卡通、不加色块）。改动先出截图给我审。

## 四、档位存储与旧存档

- 设置 `bridge.stats.favorMode` 取值改为 `vivid / normal / hard`，默认 `vivid`。已保存 `normal` 的用户得到新普通，已保存 `hard` 的得到困难（＝现行普通）。
- 楼层 meta 新增 `favorTier`（三档都写）。重算旧楼时：有 `favorTier` 按它；没有则读旧 `favorMode`——`'hard'` 按旧困难（单楼 1、每日 4，代码里保留为 `legacyHard`），缺省按困难档（与旧普通完全相同）。保证重算、重 roll 旧楼数值不变。
- `stat-log.js` META_KEYS 加 `favorTier`；`stats-runtime.js` 第 917 行附近的 favorMode 推断改为上述规则。

## 五、提示词与界面

- `stat-prompt.js` 默认 tags 段 favor 行改为带强度，附一句说明：小＝日常好感，中＝走心的互动，大＝明显打动或伤害，重大＝约会、告白、共患难或背叛决裂。模板变量加 `{{好感强度}}`。
- 设置页「好感成长」改为三段：鲜明 / 普通 / 困难。说明一行，书面语、不写数字：「鲜明：变化明显，小事攒成心意；普通：稳步增长；困难：慢热难攻略。」

## 六、改动文件

`stat-vocab.js`（强度表、近义词、推定表）、`stat-directives.js`（第四段）、`stat-favor.js`（三档 limits、倍率、心意槽）、`stat-settle.js`（applyCharacterDirective 选档、重大校验、每日一次大、meta.favorTier）、`stat-day.js`（日结算清 bigUsed）、`stat-state.js`（heart 字段默认值）、`stat-settings.js`、`stat-log.js`、`stats-runtime.js`、`stat-prompt.js`、`stats-settings-fields.js`、`fx-runtime.js`。

## 八、吃醋按芥蒂分两路（2026-11-06 追加，用户定稿）

吃醋代表在乎，不再一律扣好感。三档通用；旧楼（无 `favorTier`，即 `legacy`/`legacyHard`）仍按旧表扣 3，保证重算不变。

- **芥蒂 < 26（不满及以下）**：好感不降。
  - 好感 ≥ 50 时掷 d100，≤ 当前好感则好感按正向「小」加（走该档的正常增量与上限，鲜明档同样进心意槽），每人每天最多一次（`daily.jealousUp`）。
  - 无论是否加好感，芥蒂 +2（变动 note「吃醋」）。反复吃醋会积成芥蒂，最终转入下一路，防止刷好感。
  - 好感 < 50 时只加芥蒂 2。
- **芥蒂 ≥ 26（记恨及以上）**：好感按负向强度表扣（吃醋省略强度推定为「中」，−8），不掷骰。
  - 再掷 d100，≤ 当前芥蒂值则芥蒂再加：小 +3、中 +5、大 +8、重大 +8。此路芥蒂每日最多 +8（`daily.gained.芥蒂` 计）。
- 吃醋的芥蒂增量不受信任/了解等通用维度上限约束，只受上面两条规则。
- 修罗场信号（`stat-fx.js` 吃醋判断，现在要求 `c.to < c.from`）改为：本楼有吃醋标签即触发，不看好感是否下降。实现上给吃醋结果统一写 note「吃醋」的变动（好感或芥蒂皆可），信号按 `note==='吃醋'` 且 source 为 tag 取 target，去重。
- 门槛 50、26 写成常量（`JEALOUS_FAVOR_MIN`、`JEALOUS_GRUDGE_MIN`），芥蒂 26 与 `GRUDGE_TIERS` 的「记恨」一致。

## 九、信任分强度（2026-11-06 追加，用户定稿）

信任保留「建立慢、崩塌快」，改用与好感相同的强度字段：`[igs-stat:trust|角色名|上升/下降|强度]`，第四段可省，省略按「小」。

| 强度 | 上升 | 下降 |
|---|---|---|
| 小 | +1 | −3 |
| 中 | +3 | −8 |
| 大 | +6 | −15 |
| 重大 | +10 | −30 |

- 新三档下上升不掷 d100、无阶段倍率、无心意槽；单楼 +6、每日 +10（`daily.gained.信任`），负向不设上限。
- 正向「重大」同楼对同一角色需 `event`，否则降为「大」（复用 `capMajorStrength`）；负向重大不需要。
- 检定失败的降档规则对信任同样生效（强度降一档，小降为无）。
- **受伤后修复更慢**：发生信任负向「重大」时，角色 `trustWound = 3`（天数）；日结算 `trustWound` 减 1（不低于 0）；`trustWound > 0` 期间信任上升减半（向下取整，至少 1）。字段随楼层快照，默认 0，不进状态栏、不推表格。
- 旧楼仍走旧算法（上升 +1、下降 −4，现 `baseDelta` 信任分支），保证重算不变。了解、欲望等其他维度本轮不改。
- 提示词 tags 段 trust 行加强度与一句说明：小＝守约、小事可靠或敷衍、小谎；中＝帮忙兜底、保守秘密或爽约、被发现隐瞒；大＝危难时挺身而出或当众出卖、重大欺骗；重大＝托付生死或背叛。

## 十、八、九节的验证

在第七节的定向用例中补充：

1. 吃醋：芥蒂 < 26 且好感 ≥ 50 时 d100 过与不过两个分支（好感只在过时加，芥蒂都 +2）；同日第二次吃醋不再加好感；好感 < 50 时只加芥蒂。
2. 吃醋：芥蒂 ≥ 26 时好感 −8；芥蒂再加的 d100 两个分支；芥蒂每日 +8 封顶。
3. 吃醋：修罗场信号在好感未降时也触发；旧楼吃醋重算仍扣 3。
4. 信任：四档强度的上升与下降值；单楼 +6、每日 +10 上限；正向重大无 event 降为大。
5. 信任：重大下降后 3 天内上升减半，第 4 天恢复；删楼/swipe 后 `trustWound` 跟随快照。
6. 信任：旧楼重算仍为 +1 / −4。

## 十一、亲密门槛豁免（剧情需要，2026-11-06 用户定稿）

场景：剧情强制亲密（如双修），角色好感为负也必须进行。现行亲密门槛（`stat-prompt.js` `intimacyAllowed`：好感 >50、信任 >25、欲望 >25）不满足时提示词要求 AI 拒绝或回避，剧情无法推进。

- 人际关系页每个角色加开关「亲密门槛豁免（剧情需要）」，默认关。存在**本聊天的角色设置**里（与手改关系同一层，不随楼层快照，swipe/删楼不丢），不进状态栏、不推表格。实施前先 grep 手改关系（`applyManualRelations`/manual）的存储位置，跟随同一处。
- 开启后，该角色不再输出「拒绝或回避」约束，改为新提示词 `intimacyForced`（设置器可编辑）：「与主角的亲密是剧情所迫，并非出于好感；态度、言语与神情仍按当前关系阶段和芥蒂表现，不因亲密而变得温顺或亲近。」
- 提示词 tags 段说明补一句（对所有角色生效，不只豁免角色）：「亲密行为本身不算好感事件，好感只按主角在过程中的态度判断（体贴照顾可为感动，敷衍利用可为失望）。」
- 数值不另设算法：欲望照现有标签涨；出轨怀疑走信任（第九节强度）；芥蒂、吃醋走第八节。

## 十二、亲密消耗体力（2026-11-06 用户定稿）

- 新标签 `[igs-stat:intimate|角色名|轻/中/重]`：一个标签同时扣主角与该角色体力。轻＝亲吻爱抚，中、重按激烈程度。近义词归一进 SYNONYMS，含数字整条丢弃。只在 NSFW 开启时进提示词与结算（同欲望的判断）。
- 基础扣除（每楼，按该楼最高一档算一次，同楼多条不叠加）：轻 −5、中 −10、重 −20。
- 设置「亲密消耗体力」四段：不消耗 / 轻（×0.5）/ 标准（×1，默认）/ 重（×1.5）；四舍五入，至少 1。选「不消耗」时不扣体力，提示词里也不出现 intimate 行，标签照常解析但不结算。设置值记进楼层 meta（`intimateCost`），重算旧楼按当时档位；旧楼无此字段即无此标签，不受影响。
- 体力 <30（复用 `STAMINA_LOW`）：在场段对该角色或主角追加「很疲惫，想停下来」；主角沿用现有疲惫提示，NPC 同样文案按角色名写。
- 体力归零：主角沿用现有 `forcedRest`；NPC 归零时在场段追加「体力耗尽，亲密必须在本轮结束」。
- 当天第一次结算 intimate 标签时主角压力 −10（复用 `STRESS_DELTA.下降`，`daily` 记一次），之后同日不再减。
- NPC 没有体力条时按满值 100 建立（沿用 `barsOf` 默认值，实施时核对）。

## 十三、十一、十二节的验证

1. 豁免开关：开时提示词不出拒绝约束、出现 `intimacyForced`；关时恢复；开关在 swipe/删楼后保留。
2. 亲密非好感事件的说明出现在 tags 段。
3. intimate 标签：三档基础值 × 四档设置的扣除量；同楼多条只按最高一档扣一次；主角与角色都扣。
4. 「不消耗」时不扣、提示词无 intimate 行；旧楼按 meta 档位重算。
5. 体力 <30 与归零的提示文案（主角、NPC 各一例）；当天第一次亲密压力 −10，第二次不再减。
