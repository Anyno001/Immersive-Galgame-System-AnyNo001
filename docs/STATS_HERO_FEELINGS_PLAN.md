# 主角对角色的态度数值（双向关系）计划

2026-11-11 起草，未实施。

## 一、目标

现有数值全部是「角色对主角」的单向记录，主角对角色的态度只有一栏 40 字的手填备注「我对TA」。压测记录（STATS_RELATION_STRESS_TEST_NOTES.md 第 136 行）已经指出：在单恋、利用、单向施害这类关系里，关系名会给出与主角感受相反的结论。

本计划给主角一侧也建立一套数值。主角是有自己想法的角色，他对每个人的态度由剧情决定，不由用户代入决定；用户可以手改，也可以整个不启用。

## 二、用户已拍板

1. 数值由正文 AI 按剧情写标签，插件结算；用户可在人物卡里手改。
2. 主角一侧与角色一侧完全对称：好感、信任、了解、芥蒂、欲望五项（欲望仍只在 NSFW 开启时存在）。此前「不加 User 欲望」的决定由本次选择取代。
3. 四项作用全部要：注入提示词、关系名看双向、影响告白与恋爱判定、接上已写好的特质。
4. 设总开关，默认关闭。

## 三、数据

- 存放位置：`state.characters[名].hero = { dims: { 好感, 信任, 了解, 芥蒂, 欲望 } }`，与角色自己的 `dims` 并列，随楼层账本结算与回滚，不放聊天级目录。
- 取值范围与角色侧相同（负 100 到 100，芥蒂与欲望不低于 0）。
- 主角一侧不设好感关口、不掷骰、没有心意槽、没有单日上限以外的额外机制；每楼每项只取幅度最大的一条，幅度沿用角色侧的强度档位表。
- 欲望、芥蒂的每日自然消退沿用角色侧规则（恋爱对象的欲望不消退）。
- 新增结算版本 rev 3：只有 rev 3 的楼才解析主角侧标签，旧楼重算结果不变。
- 开关关闭时：不注入、不解析、不显示，已存的数值保留不清除。

### 初始值

- 新聊天：起始关系标签建档时，主角侧取同一档的初值（不带猜忌、心结等修饰）。
- 已有聊天中途开启：主角侧好感、信任、了解按角色侧当前值照抄一份，芥蒂与欲望从 0 开始。照抄是为了避免开启后所有人立刻显示成「单恋」，也让依赖「主角对其了解」的特质不被重置。
- 人物卡提供「按剧情估算」按钮，由辅助模型读最近剧情给出五项档位，用户确认后写入（做法同现有「按剧情拟写」）。

## 四、标签

只加一行，放在关系标签组末尾，开关开启时才注入：

```
[igs-stat:my|角色名|好感/信任/了解/芥蒂/欲望|上升/下降|强度]（主角对该角色态度的变化；只在正文写出了主角的心理、选择或用户输入表明了态度时写，角色单方面的举动不写）
```

- 欲望一项只在 NSFW 开启时列出。
- 总则第一条现在写着「主角自己的心意……都不写」。开关开启时这句改为「主角自己的心意用 my 标签写，不写进角色的标签」。
- 解析：`my` 之后第二段是维度，第三段方向，第四段可选强度；认不出的整条丢弃并记诊断。角色名按现有登记规则解析，未登记的不建档（主角侧标签不负责建档）。

## 五、注入提示词

在场角色段每个角色后附一句，写阶段词，不写数字：

```
主角对其：明确喜欢（信得过，心里有疙瘩）。
```

- 阶段词用好感九阶段；括号里的组合描述沿用 `describeCombination` 的写法，换成主角视角。
- 主角侧五项全为 0 时不附。
- 在场角色规则后加一句：「主角的心理与主动举动须符合上面写的主角态度，不得替主角改变态度；用户输入中主角的言行与此不符时，以用户输入为准。」
- 现有「我对TA」备注保留，开启注入时接在这句后面。

## 六、关系名看双向

`relationLabel` 增加主角侧参数。开关开启且两侧好感落差大时，先匹配下列双向名称，匹配不到再走现有规则表。名称为候选，待用户审定：

| 条件 | 恋爱向 | 友情向 |
| --- | --- | --- |
| 角色好感 >50，主角好感 ≤25 | 一厢情愿 | 单方面亲近 |
| 角色好感 >50，主角好感 <0 | 避之不及 | 避之不及 |
| 主角好感 >50，角色好感 ≤25 | 暗自倾心 | 有心结交 |
| 主角好感 >50，角色好感 <0 | 求而不得 | 热脸冷遇 |
| 主角芥蒂 ≥51，角色好感 >25 | 难以释怀 | 难以释怀 |
| 主角欲望 >50，主角好感 ≤0（NSFW） | 只图一时 | 只图一时 |

现有名称（两心相许、情投意合等）在开关开启时要求主角好感同样过线才成立，否则落到上表或下一条规则。

## 七、告白与恋爱判定

开关开启时：

- 角色的告白、约会事件只有在主角好感 >25（明确喜欢起）时才把该角色记为恋爱对象；不到时照常结算角色一侧的关键事件，但不置恋爱标记，人物卡显示「TA 已表白，主角未回应」。
- 主角好感之后升过 25，且该角色的告白记录仍在，自动补记为恋爱对象。
- 起始关系「恋人」不受此限制。
- 注入时，主角好感不到 25 的角色，在主角态度那句后加「主角目前不会接受其表白」。
- 亲密门槛本轮不动，仍只看角色一侧。

## 八、特质接线

现有特质文案里的「主角对其……」目前读的都是角色一侧的数值。开关开启后改读主角侧：

| 特质 | 现在读 | 改为读 |
| --- | --- | --- |
| 钓系（主角对其好感「心动」起，其好感上升减半） | 无数据 | 主角侧好感 |
| 腹黑、无口、千年狐狸、温柔刀、雷点显示（主角对其了解过半） | 角色侧了解 | 主角侧了解 |
| 结怨「你恨 TA」 | 独立标记 | 标记保留，另把主角侧芥蒂抬到「怨恨」档 |
| 舔狗（主角对其好感上升减半） | 实际减的是角色侧好感 | 待定，见第十节 |

开关关闭时以上全部维持现状。

## 九、界面

- 设置页「设置」子页加开关「记录主角对角色的态度」，默认关。
- 「其他角色」人物卡：现有数值格标题为「TA对主角」，下方加一排同样式的「主角对TA」数值格；「修改数值」弹窗分两组。
- 好感总览：每人一行右侧加主角侧好感阶段词。
- 状态栏不加条，避免变挤。
- 变动记录里主角侧条目的对象写作「主角→角色名」。
- 数据库表格模板本轮不加列。

## 九之二、其他角色改名与合并（11-11 用户追加）

问题：人物档案以名字为键，旧楼标签里写的也是旧名。路人后来有了真名（如「黑衣人」揭晓为「沈砚」），现在只能另建一份新档，旧档的好感、特质、角色卡都留在旧名下。

做法：

- 聊天级目录加一张改名表 `renames: { 旧名: 新名 }`。结算解析角色名时先查这张表，旧楼里写旧名的标签重算后自动记到新名下，不改动任何楼层原文。
- 人物卡名字行加「改名」按钮，填新名后：
  - 新名没有档案：整份档案换到新名下。
  - 新名已有档案（正文 AI 已经开始用真名，出现了两份）：提示「已有同名角色，是否合并」。合并后数值由重算得出（两个名字的标签按楼层顺序记在同一人身上），特质、角色卡、备注等以新名那份为准，新名没有的项目用旧名那份补上。
- 随档案一起换名的聊天级数据：特质、角色卡、悟性、亲密门槛豁免、「我对TA」备注、恋爱对象名单、状态、已知雷点、手改数值、声望归属。实施时逐项核对，漏一项就会出现改名后某项丢失。
- 改名后旧名仍被认作此人（正文偶尔还会写旧称呼）。人物卡名字下显示「曾用名：黑衣人」，可点掉；点掉只影响以后的楼。
- 不改场景素材别名表与立绘，那边继续由用户自己登记同组。
- 不做自动识别真名（由正文 AI 判断「这两个是同一人」容易错并），只做手动。

这一项与主角态度数值互不依赖，可以先做。
