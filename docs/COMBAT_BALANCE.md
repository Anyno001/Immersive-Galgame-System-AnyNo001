# 战斗平衡回归与接受边界

## 当前结论

助手已接受当前实战平衡，停止本轮调参：真实玩家还可通过构筑与装备获得加成。这是对现有游戏边界的接受，不是 D9 托管逐格目标全部通过。

正式敌人数值未因 D3 试调改变。成长精英基线为 96 格、6144 场、4830 胜（78.6%），36 格通过、60 格未达标；未采用的有界候选为 96 格、12288 场、7879 胜（64.1%），74 格通过、22 格未达标（偏难、偏易各 11）。两批错误、超时和动作拒收均为 0。样本量不同，失败格数不能当作同样本量的改善幅度。

本轮以 `0.40.43` 做本地存档；不推送、不创建标签。真实酒馆、手机、现场存档与真实玩家胜率未终验。保留以下阈值、失败格和复跑入口，不继续追加校准。

## 参战与验收口径

- 标准难度，单主角、单敌、满血、人物技能开启、有效胜场 `WINS=0`；无额外积分、装备、特性抽取或删卡资源。
- 八职业，`deck-seed=1,2,3`；来源分别为 `original`、`stitched`，固定敌人池种子 `balance`。
- 普通场保留起始卡组，等级 1/5/10：远逊普通至少 95%，相当普通至少 75%。
- 相当精英正式样本为 5/10 级：兑现等级免费抽卡与副本升级 3/7 次，最终 23/27 张牌、3/7 个升级副本；每个职业×等级×种子×来源格目标 50–75%。1 级精英只作压力测试，不计 D9。
- 每格还要求错误、超时和拒收均为 0；使用原始胜场与分母判定，不按四舍五入比例判定。
- 抽卡经 `planCardDraw → drawCardEntity → generateEntities → ledger.drawCard → flipCard → pickCard`，独立程序种子盲翻；本地确定性模板夹具不代表生产模型的模板选择分布。
- 升级经 `upgradableRows → ledger.upgradeCard`，依卡组顺序选首个合法副本；最终经 `deckCardLoadout → deckUnit → buildSetup` 参战。普通与精英使用独立内存账本。
- JSON `loadout` 保存全部候选、成长操作及最终逐副本牌表；不读取真实存档，不调用外部模型。

## 数据与复跑入口

原始 JSON 保留在本机 `.limcode/remote-diff/`（Git 忽略目录），不随代码存档：`d3-growth-smoke.json` 为装配冒烟，`d3-growth-repeat.json` 为确定性复跑；`d3-grown-physical.json`、`d3-grown-caster.json` 为每格 64 场的正式规则成长基线；`d3-bounded040-<archetype>.json` 为八职业各 12 格、每格 128 场的候选。本文随 Git 保存汇总、完整候选失败格、参数与复跑命令，不将本机原始数据的可用性等同于仓库已包含这些文件。

在 `app/` 下复跑单职业候选；同时替换职业与两处倍率为上表值，另取输出文件名，不覆盖既有证据：

    node scripts/combat-balance.mjs --archetypes warrior --deck-seeds 1,2,3 --levels 5,10 --rels even --tiers elite --diffs normal --sources original,stitched --runs 128 --hero-skill --brief --tune en-sts2-elite-14=0.5x0.45x1,en-sts1-act1-23=3.1x2x1,en-sts1-act2-11=1.7x1.2x1 --try elite=1.06x1.06,lv=0.04 --out ../.limcode/remote-diff/d3-bounded040-warrior-repeat.json

正式规则基线使用相同职业、种子、等级、关系档、来源及人物技能参数，移除 `--tune` 和 `--try`，改为 `--runs 64` 并另取输出文件名。

## 接受范围与后续触发

本轮不追加敌人数值调整，也不按来源分别写正式系数。构筑、装备等实战因素是助手接受现状的理由，未被纳入本轮托管样本，不能据此推算或保证真实玩家胜率。普通场小样本、固定池种子、本地抽卡夹具和真实设备未验边界继续保留；只有新的实战问题或另行授权才重启平衡校准。
