# 战斗画布贴边 + 手感 + 开战流程皮肤化 计划（2026-11-02）

> 本文件只留本地，提交时不暂存；若误推，执行完 `git rm --cached` 撤回。

## 0. 现状结论

- **不贴边**：`combat-skin-canvas.js:13-17` `canvasFit` 用 `Math.min(width/w, height/h)` 把固定设计稿（竖 390×844 / 横 1280×720）等比塞进面板，比例不符时左右对称留空。内嵌框多为竖向 → 用 390 宽竖稿，留空最严重。
- **手机拖牌带动整页**：`touch-action:none` 只加在初始方案 `.igs-combat-hand .igs-combat-card`（`combat-panel-style.js:574`）；画布皮肤手牌在 `.cx-hand`，没有，浏览器把按住拖动当滚动并发 pointercancel。
- **开战流程未皮肤化**：入口卡 `#igs-combat-entry`、日常挑战入口、准备中文案、战前对阵 lobby、入场白闪均为固定样式；lobby 只有 veil 重绘，其余八套沿用初始方案暖橙斜切。只有「开战」对撞过场（`showStageClash`）按皮肤画。
- **圆润结算金色**：soft-a / soft-c 共用 `combat-stage-fx-style.js:497-549` 的 `soft` 块，主强调 `--el/--gold:#f3d68f`，底是近黑遮罩 + 暗紫棕横带。
- **设置器皮肤选择**：`settings-host-render.js:238` 用 `segmentedInput` 排 10 个选项。

## 1. 画布贴左右边（方案 2）

**原则**：按高度缩放，画布宽度随容器伸缩；布局语义上靠右的元素改成 `right:` 定位，居中的用 `left:50%`。

1. `combat-skin-canvas.js`：`canvasFit` 返回 `{orient, scale: height/h, w: width/scale}`；最小宽度兜底取设计稿宽（容器比设计稿还窄时回退 `Math.min`，避免竖稿被挤坏）。
2. `combat-panel.js:448-451`、`combat-stage-fx.js:78-86, 278, 284`：同时写 `--cx-w`；`.sfx-canvas` 的 `--cw` 改为动态。
3. `combat-hit-fx-skin.js:14, 35, 210-211`：宽度改 `var(--cx-w)`，`canvasScale` 的除数同步。
4. **样式源头**：8 个 `*-concept-style.js` 由 `gal/战斗界面设计稿/落盘/gen-skin-css.mjs` 生成，**改生成脚本/设计稿再重新生成**，不手改产物。
   - 画布 `width:390px/1280px` → `var(--cx-w)`。
   - 右侧元素 `left:N` → `right:(设计宽 - N - 元素宽)`，数量（竖/横）：dark-a 2/3、dark-b 2/3、soft-a 2/5、soft-c 2/5、ink 2/6、mystic 8/8、tech 7/6、comic 6/17、veil 11/6。清单见调查记录（各皮肤 end/mates/piles/tray/skill/items/bag 等）。
   - 竖屏 `.hand` / `.deck` 宽度 → `var(--cx-w)`；横屏中部手牌 → `left:50%; translate:-50% 0`。
5. 皮肤 JS 内按 390/1280 写死的常量：`handLayout` w、comic `handW`、dark-a `HAND.w`、ink `FAN.w`、mystic `hand.root`、soft-a `FAN.w`、tech `handW`、veil `land.pw`，改为读当前画布宽。
6. 结算/对撞过场 `combat-stage-fx-style.js` 中 `.land .fig.foe2` 等绝对像素逐项核对。
7. **先做一套样板**（建议 soft-a 竖屏 + 横屏）出独立 HTML，在 3 种比例（手机竖、内嵌竖框、超宽横）截图给用户看，过关再铺其余 8 套。

## 2. 手机拖牌不带动页面

1. 给 `.cx-hand .card`、`.cx-trait`、出牌影子统一加 `touch-action:none`（写在公共画布样式，不进每套皮肤）。
2. 画布根节点 `#igs-cx-canvas` 加 `overscroll-behavior:contain`，内嵌模式宿主滚动容器在战斗打开期间同样 contain。
3. 拖动中 `pointermove` 已 `preventDefault`，补核 iOS Safari：必要时在手牌区注册 `touchmove {passive:false}` 并 preventDefault。
4. 敌人区 `.foes{touch-action:pan-y}` 保留（允许竖向滑动查看），但拖牌松手判定落在敌人上时不受影响——真机核一次。

## 3. 双击出牌（智能目标）

触发：双击（手机为两次轻点间隔 ≤300ms）一张可出的牌。

| 牌的目标类型 | 行为 |
|---|---|
| 无需目标 / 全体 | 直接打出 |
| 攻击单体，敌人 1 个 | 打这个敌人 |
| 攻击单体，敌人多个 | 打**当前前排**（环形站位 `is-front` 那位） |
| 格挡/增益，仅主角可选 | 直接用在主角身上 |
| 增益/治疗，可选多名队友 | 弹出头像选择浮层（候选头像 + 名字 + 当前血量，点头像打出，点外面或 Esc 取消） |

- 复用 `combat-skin-canvas.js:41` 的 `targets` 集合判定候选；打出走点选同一路径（`invoke`），不另写结算。
- 单击行为不变（选中→点目标）；双击第一下的选中态在第二下时直接消费，避免闪一下。
- 头像浮层按皮肤取色（读皮肤变量），实色不透明，不加描边。
- 不可出的牌双击照常给原因提示。

## 7. 顶栏关卡名被挤压（11-02 真机截图，圆润·野餐竖屏）

- 现象：关卡名「当着敖丙的面处理退回的报销单与白墨包裹」折成三行撑高胶囊，右侧「第 3 回合」被压成竖排一列；上方「VS 战斗中」黑条与之叠在一起。
- 原因：`soft-a-concept-style.js:225-228` `.topbar .title` 只有 padding/圆角，无单行约束；`.round` 没有 `flex:none`/`nowrap`，被标题挤窄。
- 改法（九套顶栏统一核查，改生成脚本）：标题 `min-width:0; flex:1 1 auto; white-space:nowrap; overflow:hidden; text-overflow:ellipsis`，点击/长按展开全名（复用头像详情浮层）；回合 `flex:none; white-space:nowrap`。贴边改造后顶栏宽度跟 `--cx-w` 走，长标题能多显示一些。
- 「VS 战斗中」黑条：查明是哪层（疑为阅读器战斗名牌/状态条）在战斗面板打开时仍显示，面板开着时隐藏或下移避让。

## 8. 两套圆润整体配色区分

- 现状：soft-a（野餐）与 soft-c（绘本）共用同一组变量（`--pink/--cream/--butter/--mint`，concept-style 第 222 行同值），只有战斗特效色不同（`combat-stage-fx-polish.js:230`：粉 `#f1a0ad` / 蓝 `#92b5e0`）。
- 目标：两套一眼可分，且贯穿顶栏、手牌、血条、按钮、结算。
  - **野餐**：保留粉 + 薄荷 + 奶白，格纹点缀。
  - **绘本**：雾蓝主色 + 杏/奶白 + 淡紫点缀，去格纹改纸面/蜡笔质感边，卡面花形印章改蓝系。
- 方法：生成脚本里 soft-c 单独一组色板变量，两套色值先出样板 HTML 并排给用户挑，不擅自定稿。
