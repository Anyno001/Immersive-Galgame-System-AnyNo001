## 3. 技术组织与资源分层

### 3.1 模块职责

保留 `#igs-map-panel`、`#igs-record-panel`、`#igs-overlay`、`#igs-db-layer` 及两个控制器的外部职责。四页内部结构可以重做；公共正文阅读器 DOM 不得替换。

- 在现有 `igs-ui` 内增加一个小型 `record-page-shell.js` / `record-page-shell-style.js`（拟新增路径），只负责共同标题/返回、材质、全幅遮挡与容器布局状态。它是四页复用，不发展成通用弹窗框架。
- 地图专属平移/缩放与坐标投影可独立为 `map-viewport.js`（拟新增），不堆进 `reader-host.js`。
- 心事、背包、关系可各设一个局部视图文件，统一由现有 `record-panel.js` 调度；状态源唯一，不复制三套客户端/订阅逻辑。
- 字段识别和分组只能在 `data/shujuku`；视觉层不扫描表头、不拼第二套字段规则。
- 图标继续集中在 `record-icons.js` 白名单中；补充图标也进入同一表，不从用户字符串生成 SVG。
- 不引入全局资料 store 或新增持久化选择状态。选中项、滚动、镜头只属于本次面板实例/当前数据源，关闭及切换阅读上下文时清理。

### 3.2 美术资产不等于界面截图

步骤 1 必须准备两种独立资产：
1. `map-demo-clean.webp`：与认可地图同方向的城镇、河流、桥梁底图，无名称、针、当前点、UI 边缘、文字与鼠标。
2. `scene-demo-clean.webp`：与认可三类资料页同系列的暮色河畔背景，无卡片、标题、正文或黑幕；黑幕由 CSS 画。

先放 `app/fixtures/record-pages/assets/`，用于固定视觉样例，不作为所有故事的默认城市/背景。不准直接从含文字的截图裁出局部充当干净资产；生成、编辑或重建后须检查残字/重影与取景，获助手确认才冻结哈希。

真实心事/背包/关系页使用当前阅读器已经加载的场景背景，不重新发起场景生成，不叠加两张不同背景。没有背景使用 `#16181a`；文字承托遮罩由资料页独立实现，不改背景图片本身。

### 3.3 地图底图的最小绑定契约

不另建依赖未知会话 ID 的全局配置。沿用当前只读表数据，可选字段按明确优先级识别：`地图底图` → `底图`。这是新支持的可选读取契约，不是声称历史表已有该字段。

- 对当前地图表 `uid`、当前 `parentId` 所对应的**当前层子行**，收集该字段中非空值；相同值去重后恰好一个，才绑定为本层底图。一行填写即可，同层重复相同地址允许；出现多个不同地址则显示“本层底图配置不一致”，不猜选其中一张。
- 父行自己的底图字段属于它所在的层，不能悄悄拿去作为其子层底图；进入子层重新求本层地址。可在 `docs/SCHEMA_AND_FIXTURES.md` 给出根层/室内层完整样例。
- 程序不添加列、不写单元格、不调用世界书刷新。实际资料作者可在其原本的表编辑流程提供这个可选字段；未提供仍可读地图与列表。
- 不用表名做持久化绑定，不将上一张表/上一会话地址当新地图默认值。打开时重新读当前来源；异步图片完成时核对实例及层级加载令牌，过期结果丢弃。
- 地址仅允许受验证的 HTTP(S) 或 `data:image/png|jpeg|webp`；不允许脚本协议、HTML 或用户提供的可执行 SVG。使用 `<img>` 的安全属性而非不可信 HTML 拼接，设置不发送页面 referrer。
- 本地 data 资源建议上限 8 MiB、解码最长边 4096、总像素不超过约 16M；远程图片只能在真实可检查的环节限制解码尺寸及加载超时，不虚称能在下载前验证其字节数。失败显示状态并回退，不阻塞资料页。
- 无底图、地址非法、加载失败是不同状态。无底图仅画中性坐标平面和真实标记，不绘制虚构建筑/道路；无坐标的记录进地点列表。

此方案不修改已有存储 schema。以后若增加可编辑底图资源管理，是独立扩展，不得在本轮顺手加入。

## 4. 视觉合同与双端布局

### 4.1 样式起点与冻结方式

下列是可编码的初始规格，不冒充从生图精确量出的每一个像素。步骤 2 以真实组件截图校准并冻结到一处 token 定义，后续页面不得各自改值：

| 项目 | 起点与约束 |
|---|---|
| 背景兜底 | `#16181a` |
| 主文字 | `#d8d5cf`；次文字采用有足够对比的暖灰，不大面积过低透明度 |
| 面板 | `rgba(31,34,37,.62)` 起点；黑幕承托文字，默认无 backdrop blur |
| 黑幕 | 全幅底部向上渐变；可从 bottom `.92`、中部 `.55`、顶部 `.18` 校准，标题另加轻遮罩；与场景共享背景，不盖成死黑 |
| 主边界 | 外层无粗描边、无强投影；局部格位/书册选中允许 1px 暖灰轮廓与短线，参照图片 |
| 圆角 | 面板/格位约 8px；手机地图底部面板顶部约 20px，作为明确差分而非所有卡片统一大圆角 |
| 字体 | 中文 `Source Han Serif CN`、400 常规；拉丁/日期可复用 `Cormorant Garamond`；不给缺失的细体伪造字体档位 |
| 正文 | 宽屏 17–18px，窄屏 15–16px，行高约 1.75–1.85；不通过整体 scale 缩小成不可读文字 |
| 页标题 | 宽屏约 24px、窄屏约 20px；真正几何居中，左右短线不把标题推偏 |
| 辅助文字 | 12–14px；完整名称/描述在详情可读，不以省略号作为唯一信息 |
| 图标 | 内联 SVG、`currentColor`、统一细线；返回图形约 20–22px，实际点击区至少 44×44 CSS px |
| 间距 | 基础节奏 4/8/12/16/24/32；常规窄屏水平留白 16–20px，320px 时最低 12px |

高对比背景下正文 WCAG 对比目标至少 4.5:1，控制边界目标 3:1；必要时局部加深承托，不给整张背景加破坏风格的滤镜。不得为“细”把文字做成模糊或低对比。

### 4.2 布局由容器决定

- 读取资料页的可用 `inline-size` 与高度，而不是 `window.innerWidth` 或 UA。优先容器查询；不支持时由唯一 ResizeObserver 写局部布局状态，销毁时解除。不采用窗口轮询。
- **宽屏：W ≥ 1100px。** 采用电脑图分栏。
- **中间宽度：768 ≤ W < 1100px。** 允许缩减列数/改成两栏，但保留选中详情和全部功能，不出现三栏挤压。
- **窄屏：W < 768px。** 采用移动图纵向结构；电脑上的窄浮窗同样走这条分支。
- **短容器：H < 600px。** 在上述宽度规则上叠加高度处理：不放大容器，不缩字，不强行一屏全显示。固定轻量页头，内容区滚动；地图保留可操作视口，详情提供展开/收起与内部滚动。
- 切断点/旋转后保留所选记录、当前日记篇与地图地点，不重复读库、不自动关闭。
- `height:100%` 对齐当前阅读器；100dvh 仅能用于原有全屏宿主的外部约束，不能把内嵌资料页撑到浏览器全屏。
- `env(safe-area-inset-*)` 仅在面板确实贴近宿主视口边缘时计入，内嵌/浮窗不重复补系统安全区；不渲染假系统状态栏。

### 4.3 四页的端型差异

| 页面 | 宽屏 | 中间宽度 | 窄屏/手机 |
|---|---|---|---|
| 地图 | 地图约 72%，右侧详情约 28%，详情最小约 280px | 地图 + 较窄侧栏；若地图可用宽不足 420px，切上下 | 上方地图、下方详情；默认详情约可用高的 35%–40%，可展开；短容器先保证地图可操作 |
| 心事 | 左册架/目录约 32%，右阅读约 68%；正文限制可读行宽 | 左目录约 240px + 阅读区 | 横向书册、横向可滚动篇章入口、单列正文、上一则/下一则；不把书册固定三本 |
| 背包 | 约 68% 内容区五列格位，约 32% 详情 | 四列格位 + 详情或下方详情，按最小格宽选择 | 常规 360–767px 三列；320–359px 两列，名字/数量不挤在一起；详情在格位下方 |
| 关系 | 人员索引约 22%，局部关系图约 40%，描述约 38% | 人员索引与主内容两栏，图与说明上下 | 横向人员选择 → 局部关系图 → 人物描述/关联条目；不缩三栏 |

图中“5×3 槽”“3×4 槽”“三本书”“四个人”是演示状态，不是数据上限。演示图可用不足一行的禁用空槽补齐节奏，空槽不计为真实背包容量、不可聚焦、不可点击；生产数据按实际条目展示。

## 5. 各页行为与数据合同

### 5.1 共同生命周期

- 四页互斥；打开时关闭资料入口菜单，并遮挡/禁用当前阅读器的对话、立绘、翻页层、HUD 与浮动工具。背景保留。
- 不重建阅读器根，不触发正文重新解析、发送、切楼层或重新播放打字机。
- 关闭/返回只关闭资料页；Escape、返回按钮一致。焦点回到仍存在的原入口，否则回到阅读器可用控件。
- Tab 不穿透到遮挡后的控件；Enter/Space 激活当前按钮，不触发正文翻页。只锁当前阅读器内部交互，不给 `document.body` 增加无条件全页滚动锁。
- 订阅只在打开时存在；关闭、阅读器销毁/上下文切换时解除订阅、ResizeObserver、pointer capture 与图片加载回调。
- 数据更新保持可唯一识别记录的选择与滚动；若选中记录消失，显示未选择状态，不把旧行号下的新记录当成原对象。优先使用同源唯一显式 ID；无 ID 时以来源与原记录内容核对，无法唯一确认就清除选择。重绘不能反复回滚到顶部。
- 数据文本一律转义；读取错误、无表、空表、字段不足分别表达。常规页不常驻“刷新/来源/调试”大段信息，多来源区分及缺字段提示可通过紧凑选择/可展开区域承载，不能丢数据。

### 5.2 地图

**数据：** 保留现有地点层级、0–1 坐标、显式角色与唯一场景匹配；新增第 3.3 节底图读取。当前点来自唯一匹配的当前场景，不是点击后的选中点。点击针只更新 `selectedId`，不能把当前位置移动过去。

**渲染：** 一个世界坐标平面、一个视口、同一转换下的底图与锚点。以原图自然宽高与等比缩放计算点位，禁止底图 `cover` 裁剪后继续把针按外容器百分比摆放。允许桌面/手机对同一地图等比取景不同，但锚点必须与地物一致，不为手机重新编坐标。

**交互：**
- 鼠标点击针/地点列表选中，右侧/底部显示完整名称、说明和显式相关人员；普通针、选中针（细环）与当前点（实心圆+圈）可区分。
- 拖动平移、按钮 +/− 缩放、归位恢复本层初始镜头；缩放建议范围 1–4 倍。触屏支持拖动及双指缩放，按钮可作为等价操作。
- 缩放围绕操作焦点进行；标签、图标与触控命中区保持可读大小，不跟着地图无限变小/变大。拖动超过约 6 CSS px 不派发地点点击；pointercancel/松手/销毁必须释放拖动状态。
- 手势仅在地图区域接管，详情仍可自然滚动；保留浏览器页面级缩放，不拦截全局 Ctrl/Meta+滚轮。键盘可聚焦针和缩放控件，不能只能用手势。
- 初始镜头按本层底图与标记范围拟合；若手机比例无法全部容纳，用可平移地图展示，不能拉伸底图。所有地点仍可从列表选择，选中后平移到可见范围但不改坐标。
- 原有多地图选择、进入子地点/返回上层、无坐标列表与数据提示必须保留，但采用同款紧凑样式。
- 手机详情把手对应真实展开/收起按钮；提供 `aria-expanded`，不画无行为的拖拽把手。展开可提高到约 70% 可用高度，收起保留名称和展开入口；面板长内容独立滚动，不覆盖不可达的“前往”。
- “前往”复用现有 `fillDraft`：只填空草稿，不发送、不覆盖、不改场景；成功/已有草稿/输入不可用有明确反馈。不要为了显示输入框擅自切阅读模式。

### 5.3 珍藏心事

**模型：** 新增分离的 `author`、`chapterTitle`、`date`、`body`；保留现有 `title/cells/detailCells/uid/rowIndex` 所需兼容，不将新字段要求变成拒绝旧记录的条件。

- 作者候选按顺序：`写作角色`、`作者`、`角色`；篇名候选：`篇名`、`日记标题`、`标题`、`主题`、`名称`。字段优先级按候选顺序，不受表头排布偶然左右。
- 同一来源 UID 内按明确作者分册；不同来源同名作者不擅自合并。未署名显示中性未署名册，不默认归为“我”。只有作者没有篇名时显示“未命名篇章”，作者只放作者位置，不能继续拿作者当篇名。
- 保留旧原始记录及已有合法日期规则；新 UI 的篇章列表可对全组均为合法 `YYYY-MM-DD` 的记录按最新在前显示，作为显式的新视图排序，不改变原表。非标准故事时间/混合日期保持原顺序，不虚构年份。
- 没有正文但有原始单元格仍可查看；同时出现作者、篇名与正文时各就其位。正文是纯文本、保留换行，不执行日记内 HTML。

**界面：** 书册用矩形、细书脊、SVG 书本与窄书签，禁用棕色皮革。选择书册后显示该册篇章，点击篇章显示正文与真实日期；上一则/下一则使用当前册实际顺序，边界 disabled。选中态使用细轮廓/短线，不用大色块。

电脑左右栏可分别滚动；手机选册横向滚动，正文单列，文章长时纵向阅读，不把文字压缩到图中同样行数。篇章超过三个时仍可访问，不只放图里的三个日期。恢复书册/篇章时保留相应阅读位置；主动换篇可回到新篇开头，不在普通数据刷新时滚动。

### 5.4 你的背包

复用已有物品名称与 SVG 分类，图标不识别时使用现有通用回退，不加载任意远程 SVG。

- 格位始终保留名称，即使选中也不能隐藏；数量在右下角，与名称预留独立空间。长名称格位最多两行，详情显示完整名称。
- 明确数量显示 `×值`，`0` 不能变成 `1`；缺少数量时不再无条件补 `×1`，不显示角标，详情用“数量未记录”。这是本轮显式修正旧展示默认值，单测覆盖。
- 名称、数量在详情头只出现一次；ID、来源、重复标题字段不出现在主详情。其他实际字段保留在合理的详情区域，不能为了简洁丢内容。
- 初始可未选择；参考截图用点击“旧钥匙”后的真实状态取得。桌面右侧详情与格位并列；手机详情在格位下方，选择时仅必要地滚入可见，不因数据刷新抢滚动。
- 不添加任何物品变更操作。空槽只作禁用视觉占位，非实际容量。

### 5.5 人际关系

新增纯展示模型，不能把任意描述交给关键词匹配后造关系。

支持两种明确输入，映射集中在数据层并记录到契约：
1. **人物/组织资料行**：主体 `姓名/人物/角色/名称`，身份 `身份/职业/称谓`，说明 `人物描述/描述/说明`；可选显式 `相关人员/关联人员/相关人物`。
2. **成对关系行**：明确的 `人物A + 人物B + 关系` 或 `主体 + 对象 + 关系`，两端非空且可识别才生成边；关系描述可独立展示。

- “商会势力”中的组织不能伪装成自然人；首字圆标适用于两者，身份/类别只在记录明确时展示。
- 只有“名称 + 关系”而没有另一端（已有测试样例）时，保留为主体属性/原始字段，不能凭空连向玩家。
- `相关人员` 列表可生成明确关联条目；缺关系名称就不画标签。一个关系词对应多人而无法确定分配时保留原始文本，不强行分配给每个人。
- 不从“与陈屿相识多年”这样的自然语言描述解析边；不跨来源按同名自动合并人物。无法唯一定位的相关人员可显示名称条目，不捏造其头像、身份和生平。
- 图展示当前主体的一阶显式关系，不画全库巨网。超过可读节点数时按真实记录分页，并给出明确“更多”入口；不能只渲染前三人就静默丢数据。
- 点击索引/节点更新所选对象、图与说明。页面左/上索引、局部关系图、详细描述三个部分均存在；没有足够图数据时保留同款描述/关联列表，明确提示，不以空表格代替完成版。
- 关系线用 SVG，节点为可聚焦按钮；线和按钮来自同一布局数据。标签避让节点，不被手机换行遮住。

## 6. 有序实施步骤与每步完成条件

执行顺序：**1 → 2 → 3 → 4 → 5 → 6 → 7 → 8**。步骤 3–6 有独立验收，但共享控制器/样式路径，应默认串行写入，避免并发互相覆盖。只读比对和不同截图尺寸采集可并行。每步均须读回专项 diff；失败定位在产品、夹具、测量工具之间，不盲改业务。

### 步骤 1：交接参考图、干净美术与固定样例

**改动范围：** `docs/ui/record-pages/**`（新增）、`app/fixtures/record-pages/**`（新增），不改运行时代码。

**动作：**
- 复制八图与说明，建立哈希清单与相对链接；列出不能复制到产品的图中元素。
- 准备第 3.2 节干净地图/场景资产，记录来源与尺寸。使用生图/编辑工具时实际附上认可参考图，不只靠文字重描述。
- 创建匿名固定夹具：六地点、明确当前地点、旧书店选中；三本日记且每册多篇；十物品含未知图标与缺数量；四个人及显式三条关系。另给旧表/字段缺失/多源/长内容样例。
- 建立 `visual-checklist.md`：逐页结构、组件和样式对应八图，并登记尚待校准的数字；建立截图命名与数据复现说明。

**验证/完成条件：** 八张哈希一致且相对链接可用；干净资产没有文字/针/卡片残影，地图可按同一坐标体系取景；夹具不含真实用户数据且能说明每个显示字段的来源。**干净美术与允许偏差须由助手确认后，才可把它当高保真验收底图。** 本门槛是资产确认，不要求用户再回答已确认的三项路线。

### 步骤 2：统一外壳、字体、背景与真实截图入口

**改动范围：** 现有两种面板控制器/样式、`original-reader-source.js` 的样式装配、`reader-host.js` 必要装配点；新增轻量共享 shell；`app/fixtures/record-pages/preview.html`、`app/scripts/record-pages-preview.mjs`、相关测试入口（拟新增）。

**动作：**
- 四页统一容器内全幅页头、返回、遮挡与恢复，不移动 HUD 入口，不影响普通数据库面板。
- 接入现有字体资源，检查 runtime CSS 加载与 `document.fonts`；只给资料页选择宋体，不改全局对话框字体设置。
- 落第 4 节 token、容器分支和短屏滚动。背景来自当前舞台，遮罩独立。
- 建立本地截图入口，**必须导入生产控制器/样式并注入 fake 数据客户端**，不能手写一份只为截图好看的重复 HTML。可用 Node 原生静态服务，无需引入新的测试框架；建议脚本别名 `preview:records`。
- 外壳阶段提供四页占位内容但真实生命周期，展示 1440×900、390×844、390×500 三种容器；此阶段不宣称各业务页完成。

**验证/完成条件：** 标题中心偏差不超过约 2 CSS px；返回命中区 ≥44px；默认/渐变黑幕两主题背景一致；打开后背后不可操作，关闭后阅读页、模式、焦点、背景恢复；字体已实际加载且窄屏无横向溢出。截图入口关闭/重开无残留订阅。冻结 token 和已确认视觉差异后再铺开四页。

### 步骤 3：地图从示意面板落实为交互地图

**改动范围：** `map-model.js`、`map-panel.js`、面板样式；局部 `map-viewport.js`（如需）；共享装配的必要调用迁移；地图单测/模拟/截图夹具及数据契约。

**动作：** 完整实现第 3.3、5.2 节；明确底图状态机、坐标投影、当前与选中分离、平移缩放、层级与无坐标列表、手机详情切换和安全草稿。坐标计算抽成可独立测试的纯函数，不把数学藏在 DOM 回调中。

**定向验证：**
- 同层唯一底图、缺底图、冲突、非法地址/加载失败均分开；切表/切层异步结果不串图。
- 给定坐标在桌面/窄屏/不同缩放后投影与逆变换可复验；自然宽高、留白偏移和取景偏移不能丢。
- 点击针只更改选择，当前点不移动；拖动不误触针；pointercancel 后可再次操作。
- 同名场景不擅自高亮；无坐标/重复 ID/循环等已有用例不退化。
- 草稿非空与空两种路径、宿主和阅读器输入两种入口，发送计数始终为零。
- 桌面侧栏与手机底部详情截图均对照 D-MAP/M-MAP；图层重影、坐标漂移、控件遮挡视为阻断。

**完成条件：** 固定样例可真实点针、拖动、缩放、归位、选表、进入/返回子层并正确显示详情；两端都取得来自生产组件的截图，地图主视觉不能用示意平面替代后标记完成。

### 步骤 4：心事作者选册与篇章阅读

**改动范围：** `record-model.js` 及必要的局部 diary 视图、`record-panel.js`、对应 CSS、模型/模拟测试、契约。

**动作：** 实现第 5.3 节，迁移现有控制器消费点及 `getState` 测试；同源作者分册、章节列表/日期、阅读、前后篇、焦点与滚动完整接通。

**定向验证：** 作者与标题同时出现不混用；表头换序仍正确；旧“标题+正文”和“写作角色+发生时间+正文”可读；未署名与多来源不错误合并；非标准日期不乱排；特殊字符转义；切册/换篇边界、长正文滚动、更新后稳定恢复。截图 D-DIARY/M-DIARY 必须显示同款书脊/书签与阅读区，不能用列表按钮充当书册。

**完成条件：** 模型兼容与 UI 同步交付；桌面独立目录/阅读区及手机横向选册/单列正文真实工作。人物选册、篇章选择、前后篇各有实际动作断言，不只是截图。

### 步骤 5：背包格位和按需详情

## 7. 验证方法、截图合同与通过标准

### 7.1 每个实施步骤都跑定向验证

现有最小命令（工作目录为项目 `app/`）：

```powershell
node --test tests/map-model.test.js tests/map-fill.test.js
node --test --test-name-pattern="map-panel|map-hud-entry|record-entry|record-panel|map-embedded" tests/simulate.test.js
```

测试参数放在文件前；检查实际命中用例名，不能把零命中/整文件占位的一次通过当成功。新模型/视口/视图测试按具体文件定向运行，并加入 `package.json` 的默认 `test` 或 `simulate` 入口。无须在每步重跑全量 gate。

Fake DOM 只证明结构/动作/状态，不能证明字体、CSS 计算、触控命中与真实几何。必要的新视口计算用纯函数单测；存在性断言用布尔值，避免失败时格式化循环 DOM；事件派发须到实际监听器或明确模拟冒泡。

### 7.2 必测容器矩阵

- 1440×900：四页电脑宽屏主验收。
- 1672×941：与四张电脑原图同尺寸的几何对照。
- 1024×768 与 768×1024：中间布局与平板。
- 390×844：手机主验收；另在对应原始移动图尺寸采集视觉比例对照。
- 320×568：极窄端，不横向溢出、可读可点。
- 390×500：手机楼层内嵌短容器。
- 844×390：手机横屏/矮浮窗。
- 大窗口中的 560px 宽资料容器：确认按容器而非窗口宽度切换。
- 缩放文字到 200%、长标题/长段落/大量条目时仍可达，不隐藏主要操作。

阅读模式至少覆盖网页全屏、浏览器全屏、电脑浮窗、窄屏浮窗、楼层内嵌；默认与渐变黑幕两种皮肤是主验收，其他皮肤只验证不被资料页污染；既有普通/极简显示开关的入口显隐不回归。

### 7.3 真实截图采集与对照

1. 从生产组件的 `preview:records` 固定样例或真实匿名宿主场景取得截图；关闭动画，固定数据/选中状态/背景，等 `document.fonts.ready` 及图片解码完成。保留浏览器类型、容器尺寸、DPR、资源加载结果、对应提交。
2. 每张截图记录视图状态（例如“已点击旧书店、当前位置另一个地点”），不能只保留空态来避开实现难点。
3. 参考图归一到对应画布时只做等比缩放，不能拉伸；手机地图可去除伪系统栏，并在清单明确裁切范围。原图不同纵横比不能声称像素逐点相同。
4. 输出原截图、参考并排图及约 50% 叠加图；按标题、书架/格位/地图、详情、导航分别检查。背景/示例文字的认可差异可单列，不能把整个内容区遮罩掉然后宣称相似。
5. 校准前用人工视觉与关键区域几何核对，校准并经助手认可的真实页面截图才成为后续自动回归黄金图。AI 生图没有精确字体栅格，不能用一个任意像素相似率取代审美验收。

**可量化检查：**
- 标题中心偏差 ≤约 2 CSS px；同尺寸大区分割线与参考归一位置偏差原则上 ≤2% 容器宽高，超出须记录原因。
- 规范图标/针/书签/数量角标的 DOM 框不重叠；最小点击区域 44px；正文不小于锁定字号。
- 除明确允许的书册/人员条横向滚动，页根不横向溢出；说明/章节/详情底部可滚至且不被按钮遮住。
- 字体实际命中已打包字体；文字对比达标；颜色/渐变由同一 token 驱动。
- 切换/关闭后数据库写计数为 0，发送计数为 0，遗留订阅/事件观察器为 0；原阅读状态保持。

### 7.4 人工验收的阻断项

以下任何一项存在都不能说“与参考一致”：缺独立地图美术而只交网格；定位针/文字已烘焙进底图；宋体未加载且未说明；仍为旧棕书/原始关系表；手机沿用电脑三栏；选中态、书签或数量消失；字体小到需要放大；容器/宿主滚动被误锁；选项/正文穿透；地图选中被当成当前位置；示例人物被写死；默认新造数量、关系或地图位置。

### 7.5 真实宿主与发布门槛分离

本地真实浏览器布局验证、Node 模拟、真实酒馆验收三者分别记录，不能互相冒充。真实酒馆由助手或可用 CDP 执行，重点查看移动触控、字体资源、楼层容器、当前场景背景及返回恢复。缺访问权限时交付明确复验表，不能宣称完全实机通过；main 可按既有授权用于加载候选版本，tag 必须待该候选实机通过。

## 8. 风险、失败回退与交接勾选

| 风险 | 预防/失败处理 | 不允许的替代 |
|---|---|---|
| 独立干净美术尚未存在 | 步骤 1 先交资产并确认，再做高保真主验收 | 裁带字截图、随便换城、把示意模式当主效果 |
| 历史表结构不完整 | 可选字段、原 cells 保留、只读诊断、规范样例与旧样例同时回归 | 改写数据库、拒绝旧表、猜人物关系 |
| 手机内嵌比参考图短 | 容器断点 + 短屏滚动/详情展开；真实 390×500 验证 | 撑大阅读器、字体整体缩小、控件盖正文 |
| 字体加载与资源路径 | 复用现有 build 链，等 fonts.ready，确认请求来源和解码 | 只因磁盘有 OTF 就说已生效 |
| 动态更新错选/跳滚动 | 记录身份核对、过期请求令牌、保存视图状态 | 相同行号当同一人/物、不加判断重绘回顶部 |
| 旧测试反向约束新视觉 | 明确迁移旧字号/表格/隐藏名断言，安全断言不删 | 注释测试/回退到旧 UI 换取全绿 |
| 新公共样式污染对话框/HUD | 资料页局部选择器、保护 map-panel-style 的 HUD 段 | 全局 button/h2/SVG 重置 |
| 缺浏览器或实机访问 | 分级记录已验证与待验，提供可重現截图入口和检查表 | 用 fake DOM 代替截图/真实触控结果 |
