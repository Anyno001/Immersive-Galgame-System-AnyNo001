# D-2 卡牌数值标定

## 结论与范围

本轮使用独立录入的 42 张参考卡，来源为 `.limcode/plans/combat-gameplay-overhaul/cards-ironclad.md` 与 `cards-silent.md` 的 2026-11-06 wiki Cargo 快照（CC BY-SA）。`app/scripts/combat-card-reference-data.mjs` 保存英文名、来源文件、行号与基础／升级数值；分析脚本校验来源行的英文名，并以项目 DSL 表达可估值效果。来源定位检查不等于自动核实效果语义。

样本覆盖基础 2、普通 18、罕见 15、稀有 7 张；0／1／2／3／X 费分别为 3／25／10／3／1 张；攻击 23、技能 11、能力 8 张。这是有限数值样本，不是两作全卡覆盖或逐张复刻结论。史诗、神话、个人、专属档没有独立原版样本，沿旧档目标比例外推。

D-2 当时的基础及升级联合预算通过 **38/42（90.47619047619048%）**。验收按 `passed * 10 >= total * 9`，不使用四舍五入后的比例。当时 603 张固定池定义预算合法，升级丢弃清单为空；拟合前后展开升级效果比较，未发现效果结构变化。此处仅检查定义与数值，不是全卡运行审计，也不证明升级路线忠于原版。

后续升级修正采用覆盖全 235 个模板键的版本化显式策略：87 项来源组件、98 项项目组合／自创、50 项来源未核实处理，当前逐项登记、差异与验证边界见 [卡牌来源升级对照](COMBAT_CARD_COVERAGE.md)。登记来源卡面不再为落窗而改值；本报告的样本、拟合表和测试计数保留为 D-2 阶段证据，不代表来源修订后的全池原版等价或整体平衡复验。

## 参数与推导

费用预算仍为 `{0:4, 1:8, 2:14, 3:20, X:7}`。基础牌目标维持 1.0，现有基础牌定义不改。

| 稀有度 | min | max | target |
|---|---:|---:|---:|
| basic | 0.85 | 1.15 | 1.00 |
| common | 0.75 | 2.07 | 1.80 |
| uncommon | 0.65 | 2.70 | 1.98 |
| rare | 0.60 | 3.25 | 2.16 |
| epic | 0.90 | 2.70 | 2.34 |
| mythic | 1.20 | 2.97 | 2.61 |
| personal | 0.70 | 2.43 | 2.07 |
| signature | 1.20 | 2.88 | 2.52 |

- 普通牌价值／费用预算中位数按 0.05 取整得到 `k = 1.8`。非基础档目标用 D-2 前目标乘 k；上限取旧上限乘 k 与本档样本 p95 向上取整的较大值；下限不高于旧下限和样本最小值。基础档单列不乘 k。
- `upgradeAllowance = 1.4`：样本升级价值／升级费用窗口上限的 p90 向上按 0.05 取整，且不低于旧值 1.3。它是窗口上限的余量，不是所有牌统一增加 40%。
- D-2 的 `templateUpgradeGain = 0.6` 来自普通牌升级增值／基础费用预算的中位数按 0.05 取整，仅保留为历史标定参数。当前 `solveCardTemplate` 与 `cardFromValues` 使用 `TEMPLATE_UPGRADE_POLICIES` 的 `template-v1:<key>` 策略，不据预算反解或替换升级轴；来源组件仅继承已登记差异，项目／未核实策略独立标记且继续检查升级预算。无升级必须保留 `upgradeReason`，漏登记报错。全池回归的 6074 个可解费用／稀有度变体中，5966 个带升级、108 个带原因；显式值只重建对应代表解，不声称穷举所有变量组合。
- 全样本升级价值比中位数约 1.36，p10–p90 为 1.25–1.50；按费用归一后的升级增益中位数约 0.61。
- 推导始终以冻结的 `CARD_BUDGET_V1` 为基线；重复执行不会把当前窗口继续倍乘。最终规则表与脚本建议一致。

超窗参考项：Impervious、Shrug It Off、Backstab 的本体超上限；Slice 的升级超上限。报告保留这些差异，不将拟合后的项目值冒充参考输入。

## 估值假设

- 全体目标系数保留 1.4、随机敌人保留 0.85。原版数值不能唯一反解项目遭遇敌人数；本轮不借单一系数替代 D-3 分组回归。
- `each-turn` 保留 2.5 倍内层价值，表示折现后的预期触发次数，不限制实际持续时长。回合开始型通常从下一自身回合触发，回合结束型可在打出当回合触发，持续至对局结束或无法继续触发。
- `apply-status` 的 barricade／plated／ember／juggernaut 每层估值保留 14／3／3／4。实际收益分别依赖剩余格挡、漏伤衰减、非能力牌消耗次数、获得格挡事件次数；不能仅凭整场有效断定应统一上调。D-3 需要复核这些假设。
- `damage-from-block` 按预期 8 点格挡 × 伤害单位价值 4/3 估为 10.67。8 是设计假设，不是实测均值；实战仍使用施放者当前格挡且不消耗它，技能伤害上限的保守判定保持不变。

## 兼容与数值对照

未登记来源的手写定义沿用 `fitCard`：预算合法直接返回；需要拟合时，先比较数值改动幅度，再比较距求解中心的距离，仅调整既有数值字段。带 `sourceModel / upgradeModel` 的定义原样返回，匹配校验由 schema 与预算入口负责。`FIT_TRACE` 保留旧卡构造时的手写／最终定义；它不是 `-s1` 来源修订的逐卡对照，不以旧 ID 报告证明新卡面。

账本 `normalizeSnapshot` 读取档案与条目时显式传 `{ stored: true }`，允许当前预算或 `CARD_BUDGET_V1` 之一完整合法的定义，不拼接两版上下界、不缩放卡面、不写回存储。结构、字段白名单与取值校验仍执行。新生成、`normalizeCard`、默认档案规范化及账本 `append` 使用当前模型；兼容读回不等于允许新写入旧预算专属定义。

引擎自动保留、发现、预知及策略选牌使用 `estimateBattleEffectsValue` 的既有估值；新预算与模板使用当前估值。两条链分开，预算标定不改变已保存动作中的隐式选牌。

参考与 D-2 旧手写定义有 5 处明确差异，保留在脚本 `referenceDiffs`：Body Slam 升级加格挡、Pyre 升级加即时能量、Inflame 的自伤与力量、Demon Form 的持续力量与即时升级、Footwork 升级附加格挡。后续 Body Slam 来源修订 `fx-warrior-10-s1` 已改为 1→0 费且效果不变；旧 ID 保留旧定义，其余差异尚不能据本报告称为已修复。

铁额来源修订保留 9→12 伤害与弃牌回顶 1 张；柄击来源修订保留 9 伤害／抽 1→10 伤害／抽 2。模板求解与指定数值入口共用基础窗口与显式组件升级规则；已有 setup 使用保存的目录，不重生成固定卡。
