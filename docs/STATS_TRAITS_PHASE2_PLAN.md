# 角色特质系统·第二期计划（补完未接项）

> 本地文档，不推送。前置：v0.39.68 已接入运行与界面。规则全文见 `STATS_TRAITS_PLAN.md`。
> 原则不变：特质只改数值，不碰战斗与亲密对决的牌组、主导权、回合、牌效；正文提示词不出现特质名；规则文件不 import `stat-traits.js`。

## 0. 先解决一个结构问题：事件从哪来

第一期留下的未接项里，一大半卡在同一件事上：**规则需要知道「这一楼发生了什么事」**（被夸、被拒、被背叛、被求助、被提起、久别重逢），而现在只有副模型每 30 楼评定一次时才顺带识别，平均 29 楼里事件都是空的。规则写好了也几乎不触发。

三种来源对比：

| 方案 | 做法 | 准确 | 成本 | 触发频率 |
|---|---|---|---|---|
| A. 正文 AI 写事件标签（推荐） | 在现有 `event` 标签词表里加几项（夸奖、批评、拒绝、背叛、求助、重逢），正文 AI 每楼本来就写数值标签，顺手写 | 高（写的人就是写剧情的人） | 提示词多一行词表，不多调用模型 | 每楼 |
| B. 副模型每楼识别 | 每楼多调一次副模型只问事件 | 高 | 每楼一次额外调用，费钱、慢 | 每楼 |
| C. 本地关键词 | 正文里搜「背叛」「求你」等词 | 低（「我才不会背叛你」也算） | 零 | 每楼 |

**推荐 A**。事件词表不是特质名，不违反「特质不进正文」；已有的「共患难」「交心」就是这么来的。副模型评定时的顺带识别保留，作为补漏。
同理，`stat-trait-env.js` 里那份本地关键词表（发情季、吸血、獠牙、歌声）也建议改走 A：演出标签或事件标签已有的用标签，没有的加进事件词表，删掉本地词表。

## 1. 第一批：事件接通（依赖第 0 节的决定）

| 事件 | 读它的特质 | 效果 |
|---|---|---|
| 夸奖 / 批评 | 自卑、自恋 | 已有规则，事件改为每楼来源即生效 |
| 拒绝 | 舔狗、口嫌体正直 | 已有规则，同上 |
| 背叛 | 正义使者；恩仇「决裂」 | 正义使者：该楼芥蒂上升加倍；被背叛方信任大降、芥蒂大升（沿用恩仇档位表） |
| 求助 | 老好人；「欠你人情」 | 老好人：答应求助，挂「欠你人情」或「TA欠你」；欠人情方被求助时检定加一个奖励骰（`bondDice` 已有） |
| 信仰质疑 | 狂信徒、无神论者 | 狂信徒：质疑者芥蒂上升加倍；无神论者：不受影响 |
| 耳语 | 声控 | 已有规则 |
| 重逢 / 被提起 | 白月光 | 见第 3 节 |

改动面：`stat-directives.js` 事件词表、`stat-prompt.js` 标签说明一行、各规则文件把读 `ctx.reviewEvents` 改为同时读本楼事件标签。

## 2. 第二批：要改检定与体力流程的三项

| 特质 | 现状缺口 | 设计 |
|---|---|---|
| 贵人相助 | 「每天第一次失败可重掷」 | 检定结算处加一个钩子：失败且当天未用 → 自动重掷一次，检定记录里写「贵人相助·重掷」。每日标记存 `clock`，日结算清零 |
| 赌徒 | 「押金钱：成功翻倍、失败翻倍」 | **自动押**，不加按钮：有金钱收支的检定自动按赌徒结算；当天没有任何检定则日结算压力小升。理由：加押注按钮要改检定 UI，玩家多一步操作 |
| 拼命三郎 | 「体力为零仍能行动，次日上限降一档」 | 体力扣到 0 时不触发「力竭」状态，改记 `overdrawDay`；次日日结算体力只恢复到上限减一档，再过一天恢复 |

## 3. 第三批：白月光

| 效果 | 设计 |
|---|---|
| 不在场时好感不冷却 | 已有 `noCool` 开关可直接用（同随身），一行登记 |
| 久别重逢好感大升 | 「久别」= 距 `lastSeenDay` ≥ 7 天后再次在场。本地即可判断，不需要事件 |
| 被提起时他人吃醋 | 需要「被提起」事件（第 0 节方案 A 加「提起」）；其他对主角好感 ≥ 心动的角色按吃醋结算，每天最多一次 |
| 心动进恋人多一道关口 | 好感关口表里对该角色多加一次关键事件要求，改 `stat-favor.js` 的关口判定 |
