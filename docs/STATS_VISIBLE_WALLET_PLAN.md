# 数值可见化（状态栏）与金钱/积分合并计划

本地计划，不推送。2026-11-02 定稿。

## 背景

调查结论（2026-11-02）：数值系统每楼都在注入提示词和结算，但玩家只能看到骰子判定。原因如下：

- `igs:stats-fx` 和 `igs:stats-updated` 两个事件只有发出方（`core/bootstrap.js:860`、`866`），没有任何监听。
- `scene/stats/stat-metrics.js` 的 `protagonistStatMetrics` 没有调用方，设置里的 `bars.stamina / money / stress` 三个开关不生效。
- 好感条叠在状态栏上（`reader-host.js` 约 4350 行 `overlayStatsMetrics`），状态栏默认关。

## 用户定的规则

1. **状态栏关着就不显示数值**。不自动打开状态栏，不另做飘字或弹窗；状态栏关闭时，数值只在提示词和二级页里存在。
2. **状态栏开着时，数值必须看得见**：
   - 好感条和好感增减飘字
   - 主角的体力、金钱、压力
   - 成长和阶段变化
3. **数值系统的「金钱」与卡牌战斗的「积分」合并成一种货币**，界面统一叫「金钱」。
   - 随身系统（`scene/origin/*`）的「积分」是另一回事，不在本次范围内，不要动。

## 一、状态栏开启时的数值显示

前提：所有改动只在 `statusHud.enabled === true` 且本聊天数值系统 `active()` 时生效。

1. **好感**：先核实现有链路。状态栏开着时，`overlayStatsMetrics` 叠好感条，`fx-runtime.js` 的 `diffFavorMetrics` 出 ♥ 飘字，确认这两样在只有数值系统数据源（没配表格）时是否真的出现。有断点就补，没有就不改。
2. **主角生活条**：把 `protagonistStatMetrics` 接到状态栏主角那一块，用法与 `overlayStatsMetrics` 相同。
   - `bars.stamina / money / stress` 开关决定显示哪几条。
   - 生命条：卡牌战斗开着时读战斗血量（现有 `readVitals`），否则读数值侧。
   - 金钱显示的是第二节合并后的余额。
3. **`igs:stats-fx`**：加监听，状态栏关闭时直接丢弃。
   - 状态栏开启时，把 `toasts` 和成长、阶段变化接到状态栏现有的反馈样式上，不新建组件。
   - 与第 1 条的好感飘字去重：同一楼同一角色的好感只飘一次。
4. 不改动：
   - 底部细线 `showImageNotice` 照旧。
   - 骰子判定演出照旧。
   - 状态栏关闭时的行为与现在完全一样。

## 二、金钱与积分合并

### 现状

- **数值侧**：`bars.money`，存在数值系统逐楼存档里。
  - 档位表 `DEFAULT_MONEY_TABLE`：少量 20 / 普通 100 / 昂贵 500 / 巨额 3000。
  - 「花费」超过余额时标记「买不起」。
  - 战败扣 20%（`stat-battle.js:114`）。
- **战斗侧**：主角 `points`，由战斗账本按楼层顺序推导。
  - 收入：卖出，10–150。
  - 支出：重抽 30、转职 150、重建 200、特性 100、升阶 300/600、特性槽 500–2000。
  - 余额不足时拒收（`combat/ledger.js:591-595`）。
- 两边量级相近，按 **1:1** 合并，不换算。

### 方案：一个钱包，两本流水

不搬存储，两边仍按各自的楼层回退逻辑工作。余额统一为：

> **金钱余额 = 数值侧 `bars.money` + 战斗侧主角 `points`（积分净流水）**

1. **显示**：以下位置一律显示合并余额，文案统一为「金钱」：
   - 状态栏
   - 提示词里给 AI 的「金钱」
   - 战斗面板和背包里原来的「积分」（`combat-panel-render.js`、`combat-deck-panel*.js`、`record-panel.js`、`combat-services.js` 里给用户看的文案；不改内部字段名 `points`）
   - 设置器里的「积分」文案（`settings-host*.js`、`settings-search.js`）本次不改，列进回报，等设置器迁移合回后再统一改
2. **战斗侧花钱**（重抽、转职、特性等）：写入前的预检改为「合并余额 ≥ 花费」。
   - 账本归并时，`points` 允许为负，表示战斗净支出。删掉或放宽 `combat-points-insufficient` 在归并阶段的拒收，余额判断移到写口预检（写口拿得到数值侧余额）。
   - 旧条目照旧有效。
   - 账本是纯归并、不能读数值侧，所以由 `combat-services.js` 在写入前取合并余额，通过参数传入预检。
3. **数值侧花钱**（剧情里的「花费」档位）：「买不起」的判断改用合并余额。
   - 扣款仍记在 `bars.money` 上，`bars.money` 可以为负。
   - 战败扣 20% 按合并余额计算，记在 `bars.money` 上。
4. **楼层回退**：两边各自随楼层回退，合并余额自然跟着回退，不需要额外处理。
5. **卡牌战斗关闭时**：只有数值侧，余额就是 `bars.money`。
   - 已有的积分不显示也不丢；重新打开卡牌战斗后，余额重新合并。
6. **旧存档**：直接相加，不迁移、不改写存储。

### 需要实施者先核实的点

- 数值侧和战斗侧在同一时刻的取值来源：数值侧取当前楼的 `currentStatsState`，战斗侧取 `effectiveState()`；两者都是异步还是同步，需要先查清楚。
- 卖出、拾取战利品的余额在战斗进行中是否会变（面板只读时）。
- 「买不起」在 `stat-bars.js` 里是纯函数，需要通过参数传入外部余额，不能在里面读全局。

## 测试

只跑定向测试，不跑全量、不跑 gate。新增和修改的测试：

- 合并余额计算
- 战斗花费在「积分不足但合并余额足够」时可以通过、合并余额不足时拒绝
- 「买不起」用合并余额判断
- 状态栏关闭时不显示数值、开启时显示
- `bars.*` 开关
- 好感飘字去重
