# 数值强度扩展计划（芥蒂四档 / 压力三档 / 普通困难档读强度）

2026-11-07 用户定稿方向。本地文档，不推送。接续 `STATS_FAVOR_TIERS_PLAN.md`。

## 用户定的规则

- 芥蒂加四档强度（小/中/大/重大），压力加三档强度（小/中/大）。
- 了解、欲望不动，仍只给方向。
- 鲜明/普通/困难三档成长只管好感；芥蒂、压力、信任三档共用一张表。
- 困难档改为读强度，用更小的表；普通档按需调整。
- AI 仍只写档位不写数字；强度可省略。

## 现状问题

| 数值 | 现状 | 问题 |
|---|---|---|
| 好感·普通 | 强度表 2/5/10/15，d100 失败减半，单楼 5、每日 8 | 单楼上限 5 把中、大、重大都压成 5，三者分不出 |
| 好感·困难 | 只看方向词（开心 2、感动/心动 3），d100 失败只 +1，单楼 3、每日 8 | 完全不读强度，告白与闲聊最多差 1 |
| 芥蒂 | 上升/下降固定 ±2，上升走 d100 越高越难涨，单楼 3、每日 8 | 放鸽子与当众出卖一样；60 以上几乎涨不动 |
| 压力 | 上升/下降固定 ±10 | 挨骂与亲人出事一样 |

## 一、好感：普通、困难各自一张正向表

负向三档继续共用 `FAVOR_NEG_BASE`（−3/−8/−15/−25），不改。鲜明档不改。

| 正向 | 鲜明 | 普通（改） | 困难（改） |
|---|---|---|---|
| 小 | +2（进心意槽） | +2 | +1 |
| 中 | +5 | +4 | +2 |
| 大 | +10 | +6 | +4 |
| 重大 | +15 | +8 | +6 |
| 检定 | 不掷骰 | d100 失败减半，至少 1 | d100 失败只 +1 |
| 单楼上限 | 15 | 8（原 5） | 6（原 3） |
| 每日上限 | 随阶段 15→8 | 12（原 8） | 8 |

- 普通档：表缩到 2/4/6/8，同时把单楼上限放到 8，四档都能分出来；每日放到 12，让一天一件大事加几件小事不被吃掉。
- 困难档：读强度但数值约为普通的一半，失败只给 1，「慢热难攻略」靠检定体现。
- 阶段倍率、心意槽、每日一次「大」仍只属于鲜明档。
- 关口封顶、正向重大需同楼 event、检定失败降档（强度降一档），三档照旧共用。
- 吃醋分两路（`applyJealousy`）内部按「小」走该档正常增量，自动用上新表，不另改。

落点：`stat-vocab.js` 新增 `FAVOR_POS_BASE_NORMAL`、`FAVOR_POS_BASE_HARD`；`stat-favor.js` `TIER_LIMITS` 改 normal/hard 上限，`applyFavorTier` 的 normal 分支换表、hard 分支从方向表改为强度表；`favorWeight` 按档取表（同楼去重用）。

## 二、芥蒂四档（三档成长共用）

标签：`[igs-stat:grudge|角色名|上升/下降|强度]`，强度可省，省略按「小」。

| | 小 | 中 | 大 | 重大 |
|---|---|---|---|---|
| 上升 | +2 | +5 | +10 | +20 |
| 下降 | −2 | −5 | −10 | −15 |

- 上升不掷骰、不设单楼与每日上限（与好感负向一致：伤人的事不打折）；同楼同角色仍只留一条（`dedupeDims`）。
- 下降（化解）每日最多 −10，心结不会一天解开。下降「重大」需同楼有对该角色的 event 标签，否则降为「大」（`capMajorStrength` 加芥蒂分支）。
- 提示词释义：小＝心生不满、被敷衍；中＝爽约、当面顶撞、被冷落；大＝当众羞辱、出卖、伤及其在意的人；重大＝背叛、害其失去重要之物、血仇。下降：小＝道歉、示好；中＝弥补过错；大＝替其解围、真心认错；重大＝以命相护、彻底和解。
- 吃醋芥蒂（`JEALOUS_GRUDGE_KEY`）单独记账，不变。

落点：`stat-vocab.js` 新增 `GRUDGE_UP_BASE`、`GRUDGE_DOWN_BASE`；`stat-directives.js` 第 40 行强度字段从「仅信任」放开到信任、芥蒂；`stat-favor.js` 新增 `applyGrudgeTier`（仿 `applyTrustTier`）；`stat-settle.js` `applyCharacterDirective` 加分支，`favorWeight` 加芥蒂表。

## 三、压力三档（三档成长共用）

标签：`[igs-stat:stress|上升/下降|强度]` 或 `[igs-stat:stress|角色名|上升/下降|强度]`，强度可省，**省略按「中」**（＝原 ±10，旧回复与自定义提示词结算不变）。

| | 小 | 中 | 大 |
|---|---|---|---|
| 上升/下降 | ±5 | ±10 | ±20 |

- 不设重大：压力条 0–100，+20 已是一次压垮性的事件，再大的由多楼累积。
- 提示词释义：小＝琐事烦心、小挫折／小憩、闲聊放松；中＝挨批、争吵、考试工作压力／娱乐、倾诉；大＝重大失败、亲友出事、生命威胁／彻底解决心事、长假休养。
- 亲密结算的压力 −10（`STRESS_DELTA.下降`）不变。

落点：`stat-bars.js` 新增 `STRESS_STRENGTH_DELTA`，`applyBarDirective` stress 分支读 `directive.strength`；`stat-directives.js` stress 解析多读一段强度（第一段是方向时第二段为强度，第一段是角色名时第三段为强度）；`stat-vocab.js` 新增 `STRESS_STRENGTHS = ['小','中','大']` 与近义词。

## 八、好感方向词接情绪分组

用户 11-07 提议：好感方向词直接认表情差分的 20 个情绪组，组里的词（含用户自加、自动归类新增的词）自动带上好感正负与默认强度。

### 1. 提示词方向词：18 个（以情绪组名为主）

`{{好感档位}}` 改列以下 18 个，按正负分组写进提示词。

| 正负 | 方向词 | 默认强度 |
|---|---|---|
| 正（7） | 喜悦、大笑 | 小 |
| | 欣赏、安心 | 小 |
| | 害羞、感动、爱恋 | 中 |
| 中（1） | 平淡 | 无（不结算） |
| 负（10） | 悲伤、冷淡、委屈、怀疑 | 小 |
| | 不满、嫌弃、愤怒、吃醋、害怕 | 中 |
| | 受伤 | 大 |

- 不直接用组名的三处：哭泣→受伤（哭可能是感动，正负不明）；紧张→害怕（紧张可能是心动）；平和→安心（平和等于无变化）。
- 额外三词：感动、欣赏、吃醋（没有对应组；吃醋走现有两路结算）。
- 不进提示词的 6 组：惊讶、思考、得意、无奈、心虚、动情（角色自身状态，不代表对主角的好恶；动情交欲望标签）。AI 写了仍按情绪组兜底认作平淡，不丢弃。

### 2. 旧词兼容

旧方向词 开心、心动、失望、反感 不进提示词，但结算仍认，分别等同于 喜悦、爱恋、悲伤、嫌弃 的正负与默认强度。原有数值（`FAVOR_DELTA` 旧值）只给旧楼重算的 legacy/legacyHard 档用，一个不改。旧近义词表 `SYNONYMS.favor` 一个不删。

新增近义词：敬佩、佩服、赞赏、认可、钦佩→欣赏；放心、依赖、信赖、踏实、欣慰→安心；恐惧、畏惧、惊恐、胆怯→害怕；心疼→感动；冷漠、疏离→冷淡；憋屈、冤枉→委屈；猜疑、戒备、提防→怀疑。

### 3. 识别顺序（保证旧楼重算不变）

1. 18 个方向词 + 4 个旧方向词。
2. 近义词表 `SYNONYMS.favor`。
3. 情绪组：词在用户当前 `moodGroups` 的哪一组，按下表该组取值。
4. 都不中：整条丢弃（同现状），记诊断 `stat-favor-unknown`。不猜正负。

### 4. 情绪组兜底取值（20 组）

| 组 | 认作 |
|---|---|
| 喜悦、大笑、害羞、爱恋、悲伤、冷淡、委屈、怀疑、不满、嫌弃、愤怒 | 同名方向词 |
| 哭泣 | 受伤 |
| 平和 | 平淡（组内 安心、欣慰 已在近义词表，走「安心」） |
| 紧张 | 平淡（组内 害怕、恐惧 等已在近义词表，走「害怕」） |
| 惊讶、思考、得意、无奈、心虚、动情 | 平淡 |

- 用户自建组（不在上表的组名）一律按平淡，记诊断 `stat-favor-group-unvalued`；暂不在设置页开放组取值编辑。
- 自动归类（`mood-classify.js`）新进组的词，下一楼起即可被识别，无需另配。
- 不满组里的 吃醋、嫉妒、醋意 已在近义词表，先于情绪组命中，仍走吃醋两路。

### 5. 其他规则

- 默认强度只在标签省略强度时用；写了强度以强度为准。正负决定走正向表还是负向表。
- 检定失败降档：新三档下方向保持，强度降一档（小降为无）；旧 `FAVOR_DOWNGRADE`（心动/感动→开心→平淡）只给旧楼用。
- 正向重大需同楼 event 的规则对 18 词同样生效。

### 已知取舍

- 用户之后把某词挪到别的组，重算旧楼时该词取值会跟着变。只影响被重算的楼（编辑、重刷），接受。
- 解析需要读 `moodGroups`：`stats-runtime.js` 调结算时传入当前 `userAssets.moodGroups`，`stat-directives.js` 好感解析多一步组查找。

### 落点

- `stat-vocab.js`：新增 `FAVOR_WORDS`（18 词，含正负与默认强度）、`FAVOR_PROMPT_GROUPS`（提示词按正负分组）、`MOOD_GROUP_FAVOR`（20 组兜底表）、`favorFromMoodGroup(word, moodGroups)`；`FAVOR_DIRECTIONS` 改为 18 词 + 4 旧词；`FAVOR_DELTA` 旧值保留供 legacy。
- `stat-directives.js`：好感解析第 3 步；解析时把正负写进 directive（`sign`）。
- `stat-favor.js` / `stat-settle.js`：正负判断从 `FAVOR_DELTA[d.value] > 0` 改为统一的 `favorSign(d)`；`favorStrength` 的推定改读 `FAVOR_WORDS`；`constrainFavor` 新档改为只降强度。
- `stat-prompt.js`：`{{好感档位}}` 改为按正负分组输出。

测试补：旧 8 词与旧近义词在旧楼重算结果不变；18 词正负与默认强度；哭泣组词→受伤；平和组「安心」走正、「平静」平淡；紧张组「害怕」走负、「焦虑」平淡；自建组按平淡；未知词丢弃。
