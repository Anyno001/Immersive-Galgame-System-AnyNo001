# 数值系统新手版面 + NPC 相对档计划

本地计划，不推送。2026-11-02 与用户确认定稿。前置：`STATS_VISIBLE_WALLET_PLAN.md`（状态栏显示、金钱合并）先完成，「战斗」侧栏迁移已合回。

## 一、设置页改版（只改排版与文案，不改功能和存储路径）

用户反馈：没有 CoC/D&D 经验、只懂 RPG 的玩家打开数值页束手无策。原因：
- 第一项就是「规则体系：CoC / D&D」这类术语。
- 真正的起点「本聊天 → 快速开始 / 建卡」排在页面最底，建卡还收在折叠里。
- 全局玩法、本聊天角色、技术配置平铺在同一页。

现状模板：`app/src/visual/igs-ui/settings-tabs.js` 的 `STATS_TEMPLATE`。取值：`settings-host-render.js` 的 `statsValues`。字段渲染：`stats-settings-fields.js`。

新版面，自上而下：

```
数值系统                                [● 启用]
好感、技能、体力和金钱由脚本掷骰决定，AI 只负责把结果写进剧情。
（卡牌战斗开启时的那行提示保留）

① 我的角色（本聊天）
  未开始：  [快速开始]  [自己建卡]
  自己建卡：职业名 / 定位、六项属性加点（力量 敏捷 体质 智力 感知 魅力，显示剩余点数）、技能（勾选 + 自己添加）
  已开始：  角色卡一览（属性、技能、生命/体力/金钱）、[编辑]  [暂停本聊天]

② 玩法
  骰子手感：百分骰（结果更看运气） / 二十面骰（属性越高越稳）
  剧情中的检定：自动 / 关键时刻让我手动掷 / 关闭
  选项旁显示成功率、显示掷骰卡、好感不够时角色会拒绝

③ 其他角色
  新角色出场时：自动生成数值 / 提醒我 / 不生成
  [为缺数值的角色生成]  [补全新技能]

▸ 高级（折叠）：同步到数据库表格（含模板下载与列映射）、提示词、存档与记录、新聊天是否询问、好感条右侧显示、重要角色登记、新技能补全方式、按玩家输入匹配技能
```

要点：
- 「骰子手感」底层仍是 `bridge.stats.ruleset`（coc7 / dnd5e），只换显示名和说明；页面上不出现 CoC、D&D 字样，在高级里可以注明对应的规则名。
- 「剧情中的检定」底层是 `storyCheck`（preroll / manual / off），去掉「每楼 10 对骰」这类实现细节。
- 「已开始」状态下的角色卡一览：先核实存档面板（`renderStatsArchive` 的「主角技能」「角色卡」）能否复用。不能复用时，第一版把「主角技能」折叠挪进 ①，其余照旧。
- 建卡里的「自己添加技能」：先核实现有建卡字段是否支持自定义技能名（「特有技能」）。支持就沿用，不支持就回报，不要新造存储。
- 文案规则：书面语，不用口语和祈使句；中文和英文之间不加空格；不写内联 style，复用现有 class。

## 二、NPC 技能改为相对主角的档位（偏移，初次登记时冻结）

现状：`scene/stats/stat-sheets.js` 的 `SKILL_TIERS`（未学 / 入门 25–45 / 熟练 50–70 / 精通 75–85 / 大师 90–95）由辅助模型给档位，`sheetFromTiers` 用 `bandValue` 换算成绝对值，存进角色卡。

改为：
1. **主角**：照旧，填绝对数值。
2. **NPC 技能档**：改为相对主角的六档，辅助模型只给档名。

   | 档名 | 生疏 | 略逊 | 相当 | 擅长 | 精通 | 大师 |
   |---|---|---|---|---|---|---|
   | 百分制偏移 | −30 | −15 | 0 | +15 | +30 | +45 |

   - 换算：NPC 值 = 主角同项值 + 偏移，夹在 5–95。主角没有这项技能（未学或不存在）时，以 50 为基准。
   - 同档内用现有 `bandValue` 种子加 ±5 的确定性抖动，避免整齐划一。
   - 二十面骰模式下读的是同一个存储值，由规则集换算修正，不另存一套。
3. **冻结**：换算在 NPC 首次生成数值卡时完成，结果存成绝对值，之后不随主角变化。旧存档里已有的 NPC 卡不改。
4. **兼容旧档名**：辅助模型回了旧档名（入门 / 熟练 / 精通 / 大师）时，按旧的绝对区间换算，不报错。
5. NPC 的六项属性本次不改，仍用 `ABILITY_SCORE_TIERS`。
6. 提示词里给辅助模型的档位说明同步改成相对档，写明「相对主角」。

## 三、NPC 成长

现状：只有主角成长。检定成功时打勾，日结算（`scene/stats/stat-day.js` 的 `grow` / `growSkills`）掷 d100 决定是否成长。

改为：
1. **在场检定打勾**：NPC 在场且作为检定一方（对抗检定的对手、协助者）时，用到的那项技能打勾。
2. **日结算掷骰**：日结算时，NPC 打过勾的技能也掷一次。规则与主角相同，成长概率减半，每次成长幅度与主角相同。
3. **剧情成长标签**：剧情明确写了苦练、拜师之类的长期成长时，AI 可以给 `[igs-stat:grow|角色|技能]`（具体语法沿用现有标签风格）。脚本给该技能加一次成长。同一角色同一技能每个游戏日最多一次。AI 不给数字。
4. 不在场、没有检定的 NPC 不变。
5. 成长记录进现有的变动记录。状态栏开着时，按 `STATS_VISIBLE_WALLET_PLAN` 的反馈方式显示，关着时不显示。

## 四、状态栏常驻主角区（11-02 用户确认）

现状（`f7a97275`）：主角的生命、体力、金钱、压力条只在说话人是主角时显示，旁白页和其他角色说话时看不到。

改为：状态栏开启、且本聊天数值系统启用时，状态栏里常驻一块主角区，不随说话人切换。
- **显示内容**：四条由 `bars.*` 开关决定。生命条只在卡牌战斗开启时出现。
- **样式**：复用状态栏现有的角色块，用同一套 class 和 slot 色，不新建组件。
- **说话人是主角时**：只显示一块，不重复显示两块。
- **入口**：现有的 `statsProtagonistLookup` 和 `reader-host.js` 约 4361 行。实施前先读状态栏渲染（`status-hud-model.js` 及其渲染文件），确认多角色块的排布方式，主角区放在最前。
- **状态栏关闭时**：仍然什么都不显示。

## 五、世界书里的角色自动登记（11-02 用户确认）

现状：`core/stats-runtime.js` 第 64–72 行的 `defaultResolver` 只认三类名字：已登记的角色、当前角色卡名、群聊成员。`bootstrap.js` 没有传 `resolveCharacter`。

后果：在多人世界书卡里（卡名不是角色名），AI 给世界书角色写的好感标签会被丢弃，好感永远不动。用户主要玩这类卡。

改为：世界书里有条目的角色，也按重要角色自动登记（`register: 'auto'` 时生效，「仅手动」档不变）。
1. **解析器保持同步**：解析器在结算里同步调用，不能在里面查世界书。由 `bootstrap.js` 维护一份「世界书角色名」缓存，传入 `resolveCharacter`（在默认三类之外多认缓存里的名字）。
2. **缓存来源**：复用现有的 `statsWorldInfo`（`createImageWorldInfoSource`，第 800 行，已遵守世界书排除设置）。对「标签里出现过、但还不认识的名字」做异步查询：查到以该名字为关键词或标题的条目，就记入缓存。
   - 缓存按聊天作废。
   - 每个名字只查一次，查不到的也记住，避免反复查。
3. **首次漏掉的那一楼要补算**：第一次见到某个名字时，缓存里还没有它，这一楼的标签会被丢弃。异步确认之后，重新结算这一楼（复用现有的单楼结算 `settleAt`，不要另写结算），保证她第一次出场的好感变化也能记上。
   - 补算只针对最新楼，旧楼不回溯。
4. **排除**：主角名、`{{user}}`、「系统」「旁白」等非角色名。这一份排除和修罗场规则一致：系统和主角都不算。
5. **登记后照常走「新角色出场时」**：按提醒、自动生成或不生成处理数值卡。
6. **诊断**：登记成功和查不到都记一条诊断（沿用 `diag`），不弹提示。

## 测试（定向，不跑全量与 gate）

- 相对档换算：主角有、没有该技能，上下限夹取，旧档名兼容
- 冻结：主角成长后 NPC 值不变
- NPC 成长：打勾、日结算减半概率（固定种子）、剧情标签每日上限
- 设置页：新分区顺序、骰子手感映射到 ruleset、未开始和已开始两种状态的显示
- 常驻主角区：状态栏开、数值启用时，不论说话人都显示；说话人是主角时不重复；状态栏关时不显示
- 世界书登记：缓存命中时登记；首次未命中，异步确认后补算最新楼；「仅手动」档不登记；主角、系统名排除；查不到的名字不重复查询
