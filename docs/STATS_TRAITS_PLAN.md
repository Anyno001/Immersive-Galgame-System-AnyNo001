# 角色特质系统计划（细化稿，待拍板）

2026-11-07 起草。本地文档，不推送。把散落各处的角色标记收成一套「特质」：一张登记表、一种存法、一块界面、副模型评定、剧情标签增减、挂上后有效果说明。只对 `strengthRev ≥ 2` 生效。

## 一、用户已定

- 剧情中途可增减特质，由副模型判定（见第六节）。
- 建档 / 补全时由副模型按人设挂特质，用户可改；手动改过的以手动为准。
- **正文 AI 拿不到任何性格特征（11-07 用户定）**：它只按剧情输出事件与强度（如压力上升 大），倍率在结算里静默生效。特质名、特质清单、效果一律不进正文提示词；`trait` 标签不给正文 AI 写。唯一例外是不告知就会写错事实的存在类（已故、无实体、失忆、不眠、附身），各注入一句客观事实，不含性格。
- 挂上 / 摘下特质时给一条小说明，写清效果。

## 二、特质与状态

- **特质**：角色本身的设定，进本系统。
- **状态**：剧情中发生、由数值驱动的（离体、伤势、压力转换、宿仇、痴迷），仍由结算管，只在角色卡上并列显示。

## 三、特质表

倍率只作用于该角色自身的数值；**全部特质只改数值（好感 / 信任 / 了解 / 芥蒂 / 欲望 / 压力 / 体力 / 金钱 / 伤势 / 检定骰），不改战斗与亲密对决的牌组、主导权、回合与牌效**（11-07 用户定）；可读对决、战斗的胜负结果作为事件。「主角」列为主角可否使用。注入列：无＝不进提示词。

原则：只收会改变结算的；说话与行为由人设决定，特质只让数值往这个属性的方向变（11-07 起傲娇、腹黑等可收，见「恋爱人设」组）。倍率叠加相乘，单项结果夹在 ×0.5 到 ×2 之间（11-07 定）。

剧情变化示例（副模型判定）：受创后获得脆弱、治愈后失去；黑化获得病娇；喝下忘情水获得失忆；卧底被揭穿失去伪装身份；角色死去获得已故。

## 四、存法与代码

1. 登记表 `app/src/scene/stats/stat-traits.js` 的 `TRAIT_DEFS`：键、显示名、分组、互斥、主角可用、效果说明（一句，界面与小说明共用）、评定提示语、注入句（可空）。新增特质只加表项。
2. 存档：`catalog.traits {名: {键: {on: true, src: 'auto'|'manual'|'story'}}}`；悟性存 `aptitude: {v: '出众', src}`；附身存宿主名。旧字段 `aptitude`、`intimacyForced`、布尔式 `traits` 读档时迁移，写档只写新位置。
3. 结算各处改调 `hasTrait(state, 名, 键)` / `traitScale(state, 名, 维度, 方向)`，不再自己读字段。
4. 互斥：后挂的顶掉先挂的，小说明里写明替换。

## 五、副模型评定

- 时机：角色建档、补全数值、开局评定（`heroSkills` / `sheetGen`）时，由副模型（`resolveSecondaryLlm`）按人设与世界书条目一并给出特质与悟性档。
- 规则：人设明确写了才给，没写不给；每个角色最多 3 项（悟性不计）；只能从登记表里选，表外输出丢弃。
- 评定提示词只列特质名与一句判定依据（如「脆弱：人设写明心理脆弱、有创伤、易崩溃」），不列倍率。
- 用户手动改过（`src: 'manual'`）的项不覆盖、不删除。
- 未配置副模型时跳过评定，不报错。

## 六、剧情中途增减（副模型判定）

- 正文 AI 不知道特质存在，不写 `trait` 标签。
- 触发：本楼出现重大事件时，结算后异步调副模型复核相关角色——压力上升「极大」、`break` 转换、romance 结束、救命 / 舍身相护 / 替人挡刀、背叛 / 重伤 / 害死亲友 / 复仇得手 / 和解、死亡 / 失忆 / 身份揭穿等关键词，或用户在角色卡点「按剧情复核特质」。
- 副模型读本楼与前几楼正文、该角色当前特质，按登记表输出获得 / 失去（只能从表内选）；不触发就不调，不每楼跑。
- 同一角色同一特质每天最多变一次；剧情变化优先于开局设定，手动设过的项照样可改，`src` 改为 `story`，并弹小说明。
- 未配置副模型时只保留手动与开局评定。

### 触发与发送（11-07 用户定）

分两步：**扫**是本地看标签，不调模型；**发**才调副模型。

**1. 扫（每楼，本地）**
- 每楼结算后检查本楼的数值小标签（`stress|…|极大`、`break`、romance 结束、救命 / 死亡 / 失忆 / 身份揭穿类事件标签等）。命中即进入「发」。
- 另设定期兜底：距上次发送满 N 楼也进入「发」。N 默认 30，设置里可改，0 为关闭。用来抓纪要里慢慢积累、但单楼不够「大」的变化。
- 只算本楼标签点名的角色；定期兜底算这 N 楼里标签点名过的角色。

**2. 发（调副模型，后台异步，不阻塞结算）**
- 正文：最近三楼 AI 楼层及其对应的用户楼，共 6 楼。
- 纪要表：数据库内置的「纪要表」，取最近 10 行（用户每 3 楼 AI 回复记一行，10 行正好覆盖默认 30 楼的间隔；每行约 250 字，合计约 2500 字）。行数跟随 N 自动算：N÷3 向上取整，至少 3 行、至多 20 行。
- 恋爱日记表：该表按角色名一人一组记录。按本次涉及的每个角色，用角色名列匹配（含 IGS 已登记的别名），每人取最近 3 行；没有这张表、没有角色名列或没有匹配行就不带。多人时分角色标注后拼接。
- 附每人当前特质、关系状态与近期数值变化摘要。
- 表名按「纪要表」「恋爱日记表」精确匹配（经 `shujuku/client.js` `readTables`）；读不到表时只发正文与摘要，不报错。

**规则**
- 每次每人最多变 1 项；有明确依据才改；上一次刚变的项这次不能改回。
- 同一角色同一特质每天最多变一次。
- 没有变化不弹通知。
- 角色卡「按剧情复核特质」按钮直接走「发」，素材相同。
- 未配置副模型时整套跳过，不报错。

## 附：倍率公式与算例（11-07，交隔壁做平衡性）

### 公式

正文 AI 只写「角色 / 维度 / 方向 / 强度档」，以下全部由 IGS 结算：

```
倍率   = 特质A × 特质B × …（夹在 0.5 到 2 之间；倍率 >1 时上限同乘倍率，见「平衡定稿」）
增量   = 基础值 × 系数 × 倍率                  （四舍五入，至少 1）
         普通档另掷 d100：大于当前值才全额，否则减半（至少 1）
最终   = min(增量, 单楼剩余额度, 每日剩余额度)  ← 只对上升；下降不设上限
```

现有基础值表（新楼 strengthRev ≥ 1）：

| 维度 | 上升（小/中/大/重大） | 下降 | 单楼 / 每日上限 |
|---|---|---|---|
| 好感·鲜明 | 2/5/10/15 × 阶段倍率（1/0.8/0.6/0.4），不掷骰，小强度攒心意槽 | −3/−8/−15/−25 | 15 / 随阶段 15→8 |
| 好感·普通 | 2/4/6/8，掷 d100 | 同上 | 8 / 12 |
| 好感·困难 | 1/2/4/6，掷 d100，失败只给 1 | 同上 | 6 / 8 |
| 信任 | 1/3/6/10，不掷骰；受伤期减半 | −3/−8/−15/−30（重大记 3 天受伤） | 6 / 10 |
| 芥蒂 | 2/5/10/20 | −2/−5/−10/−15 | 上升无 / 下降每日 10 |
| 吃醋芥蒂 | 3/5/8 | — | 每日 8 |
| 了解、欲望 | 每条 ±2（掷 d100） | ±2 | 同普通档 |
| 压力 | 5/10/20/极大 50 | −5/−10/−20 | 无 |

位置：`stat-favor.js`（applyFavorTier / applyTrustTier / applyGrudgeTier / applyDim）、`stat-vocab.js`（*_BASE 表）、`stat-bars.js`（STRESS_STRENGTH_DELTA）。倍率插入点：各函数里 `base * coef` 处改为 `base * coef * traitScale(...)`。

### 算例（普通档）

1. **恋爱脑（好感升降 ×1.5）**，林夏好感 30，`favor|林夏|开心|中`：基础 4 → 掷 72 通过 → 4×1.5=6 → 36。掷 18 失败 → 3 → 33。慢热（×0.5）通过时 2 → 32。
2. **恋爱脑 + 「大」**：6×1.5=9，被单楼上限 8 截成 8。
3. **恋爱脑下降**，`失望|中`：−8×1.5=−12，30→18（下降不设上限）。
4. **脆弱（压力 ×2）**，压力 30，`stress|林夏|上升|极大`：50×2=100 → 130 封顶 100；本楼前 <70，当楼进入极限。无特质 → 80；坚韧（×0.5）→ 55。
5. **傻白甜（信任 ×2）**，`trust|上升|大`：6×2=12，被单楼上限 6 截成 6。

### 待平衡的问题

- （已定，见下）**上升类特质常被上限吃掉**（算例 2、5、6），下降类不受影响 → 特质存在感不对称。两种方案：
  - A（推荐）：倍率 >1 时，单楼 / 每日上限同乘倍率（恋爱脑单楼 8→12）。
  - B：上限不变，特质只在小、中强度上看得出。
  - 倍率 <1 时两案结果相同。
- 下降 ×1.5 不设上限（已定：单楼保护）：恋爱脑一次「重大」失望 −25×1.5≈−38，是否需要单楼下限保护。
- 叠加夹值 0.25–3 是否合适（已定：0.5–2）；多特质叠到 ×3 的组合（病娇 × 醋坛子）是否需要专门压低。
- 脆弱 + 极大 = 一楼拉满：设计如此（用户 11-07 定），平衡时不要削掉，只核对普通「大」×2=40 是否过频触发极限。
- 建议平衡方式：写一个不进 build 的小脚本，固定随机数，对每个特质跑 30 楼典型序列，比较有无特质的终值与到达各关口的楼数。

### 平衡定稿（11-07，用户选 A，其余交我定）

1. **上限随倍率放大（方案 A）**：倍率 >1 时，单楼和每日上限都乘以倍率（四舍五入）。倍率 <1 时上限不变。
   - 恋爱脑好感·普通：单楼 8→12、每日 12→18；傻白甜信任：单楼 6→12、每日 10→20。
2. **叠加范围收窄为 0.5–2**（原 0.25–3）。单个特质最大就是「加倍」「减半」，多个叠加也不超过这个范围，界面文案「加倍」「减半」不会说错。
   - 病娇 × 醋坛子吃醋芥蒂：原来 ×3，现在 ×2 → 中档 5×2=10，每日上限 8×2=16。
   - 坚韧 × 宽容这类双减的，下限 ×0.5，至少还有 1 点变化，不会完全没反应。
3. **下降加单楼保护**：下降仍乘倍率，但一楼最多掉「无特质时重大档」的 1.2 倍，并且不掉过关系阶段下限一档以上。
   - 好感一楼最多 −30、信任 −36、芥蒂下降 −18。恋爱脑重大失望 −25×1.5=−37.5 → 截成 −30。
   - 小、中档不受影响，恋爱脑「容易伤心」照样看得出。
4. **脆弱保持原样**：「极大」×2 一楼拉满按用户 11-07 定稿不动。普通「大」×2=40 的频率在模拟脚本里核对：若 30 楼内进入极限超过 2 次，把脆弱对「大」档的倍率降为 ×1.5（「明显加快」），「极大」仍 ×2。
5. **掷骰不变**：普通档 d100 判定在乘倍率之前，特质不改掷骰概率，只改通过 / 失败后的幅度。
6. **验收数字**（模拟脚本固定随机数，30 楼典型序列）：
   - 加成型特质到达同一关系阶段的楼数，比无特质少 25%–45%；减弱型多 40%–80%。
   - 任何组合一楼上升不超过无特质同档单楼上限的 2 倍，下降不超过第 3 条的保护值。
   - 若超出范围，只调该特质的系数，不动公式和上限规则。
